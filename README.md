# RouterOS 網路基準（topo-mikrotik）

由 **MikroTik RouterOS** 的 CLI 輸出，一次建立網路現況基準（Single Source of Truth）：拓樸、介面、VLAN、MAC／IP 位置、路由、防火牆規則，並列出資料之間的矛盾與缺漏。

- 純前端、**零相依套件**（不需安裝；分層版面用的 ELK.js 已放在 `vendor/`）、可**完全離線**：直接雙擊 `index.html` 即可使用
- 資料只在瀏覽器內處理，不會傳到任何地方
- 約 1000 台設備一次建立約 3 秒
- 每筆資料都能回溯到原始輸出的檔案與行號；推論結果會標示為推論

## 快速開始

1. 開啟 `index.html`（`file://` 即可，不需伺服器）。`main` 分支也會由 [deploy-pages.yml](.github/workflows/deploy-pages.yml) 部署到 GitHub Pages（<https://sinnoken.github.io/topo-mikrotik/>），一樣只在瀏覽器內處理。
2. 按 **建立基準…** → **載入範例資料**（已有基準時，從頁首的 **資料中心** → **讀入收集檔…** 開啟同一個對話框）。範例刻意放了幾個問題，可以先看檢查結果長什麼樣子。
3. 要用自己的網路：依 [收集清單](docs/收集清單與輸入格式.md) 收集每台 RouterOS 的輸出（**所有 print 都要加 `detail without-paging`**），合併成一個收集檔後貼上或選擇檔案。
4. 多台設備可在 WSL／Linux 用 SSH 批次收集，產生可直接載入的收集檔：

   ```bash
   cp tools/devices.csv devices.csv        # 改成自己的設備清單
   ./tools/collect.sh devices.csv --dry-run
   ./tools/collect.sh devices.csv --output collection.txt
   ```

   設備清單格式、選項、只重收失敗的指令與安全注意事項見[收集清單 §0](docs/收集清單與輸入格式.md#0-批次-ssh-收集器wsllinux)。

## 功能一覽

畫面分三塊：左側是檢查結果、覆蓋率、清單、比對與處理紀錄；中間是拓樸圖、修正計畫、比對、收斂趨勢（分頁切換）；右側是詳細資料。頁首的「資料中心」集中這一輪所有的輸入與輸出。每項功能的操作方式見[設計說明 §12「畫面操作」](docs/設計說明.md#12-畫面操作)。

| 功能 | 做什麼 |
|---|---|
| 檢查結果 | 依[基準檢查規則](docs/基準檢查規則.md)列出錯誤、警告與提醒，可依規則或依設備分組；每筆都附證據行號、常見原因與處理建議 |
| 覆蓋率 | 每台設備收集了哪些資料、缺什麼、哪些指令收集失敗；可由未收集的設備產生 devices.csv 草稿 |
| 拓樸圖 | 只畫 L2 鄰接（LLDP／CDP）；沒有 LLDP 的設備以推論鏈路表示，終端以「未知對端」畫在所屬設備下；MNDP 只證明廣播網域可達，不畫線 |
| 詳細資料 | 鄰居、OSPF、介面、VLAN、MAC、路由與收集到的原始輸出；設備的防火牆畫面列出規則、WAN／LAN 判斷（推論）與管理服務 |
| 搜尋與路由追蹤 | 依設備名、MAC、IP、VLAN ID 或介面描述搜尋；路由追蹤逐跳顯示（含 ECMP 與回程） |
| 處理紀錄 | 每筆檢查結果的處理狀態（待處理、已排程修復、可接受、誤報、已修好、回歸），一輪輪收集後判定是否已修好，畫出收斂趨勢；只存在這個瀏覽器，可在資料中心匯出與匯入，也會放進工作包 |
| 修正計畫 | 依選取的檢查結果產生每台設備的 `.rsc`（套用、回復、驗證）；目前 F01、F02、F06 可產生停用規則的指令；A12（DNS／NTP 伺服器不一致）可選擇改成多數（推論）或某一組的值，或標為可接受。**本工具只產生文字，不會連線或改動任何設備** |
| 比對 | 與預期資料（`ssot-expected/1`）或之前匯出的舊基準比對，列出新增、移除與變更；可只看新出現的檢查結果 |
| 資料中心與工作包 | 這一輪的輸入（收集檔、上一輪基準、處理紀錄、命名規則、預期資料）與輸出集中在一處；工作包是一個不壓縮的 ZIP，內含收集檔、基準、處理紀錄、命名規則、預期資料、報表與 patch，讀回時核對是不是同一輪，再一次帶回上一輪的基準與處理紀錄 |
| 匯出 | 在資料中心：基準 JSON、檢查結果 CSV／Markdown、預期資料、拓樸圖 PNG、處理紀錄、devices.csv 草稿 |
| 儲存 | 基準與輸入存在瀏覽器（IndexedDB），下次開啟自動還原；按「清除」只清除基準與輸入 |

頂端的基準摘要是該份 Snapshot 的檢查結果與收集完整度，**不代表即時網路健康狀態**。

## 開發

只需要 Node.js（CI 使用 Node 22／24），不需安裝任何套件，也沒有 build 步驟。提交前執行：

```bash
npm test
git diff --check
```

其他指令、測試的種類與擴充方式見[開發指南](docs/開發指南.md)。

## 注意

- 這是 topo-ssot 的 **MikroTik 專用版**，與多廠牌版並存時互不影響（瀏覽器儲存名稱不同）。
- 解析器依 RouterOS 文件與慣例撰寫，測試資料由程式產生，**尚未用真實設備輸出驗證**。RouterOS 7 為主，6.43 以上大致可用。
- 支援範圍與限制見 [docs/收集清單與輸入格式.md](docs/收集清單與輸入格式.md) 第 4 節。
