# 文件導覽

`docs/` 底下每份文件回答一個問題。一份資訊只寫在一處，其他文件用連結指過去，避免多份各自走樣。

## 分工原則

| 文件 | 回答 | 不寫 |
|---|---|---|
| [路線圖](路線圖.md) | 要做什麼、依什麼順序、做到什麼程度算完成 | 已實作的設計、決策的理由 |
| [架構決策（ADR）](架構決策/README.md) | 為什麼這樣決定：背景、選項與取捨 | 規格的全文（只連結到程式或文件） |
| [設計說明](設計說明.md) | 已做好的東西怎麼運作：模組、資料模型、推論規則、版本紀錄 | 還沒做的計畫 |
| [多層網路架構圖 實作規格書](多層網路架構圖_實作規格書.md) | 多層架構圖的需求，與本工具的對應和狀態 | 實作細節（連結到設計說明） |

功能完成時，設計從路線圖移到設計說明，路線圖只在「已完成」留一句摘要；做法有取捨時另寫 ADR。

## 各份文件

| 文件 | 回答什麼問題 | 給誰看 | 什麼時候更新 |
|---|---|---|---|
| [路線圖](路線圖.md) | 接下來要做哪些功能、順序與依賴、負責的 agent、完成條件 | 使用者、主對話與各 agent | 排程改變、開始或完成一項時 |
| [架構決策](架構決策/README.md) | 影響整個專案的決策為什麼這樣做 | 要修改相關設計的人與 agent | 有新的決策（新增一份）、使用者做出決定、待辦完成（標「已處理」）、決策局部調整（加「修訂」） |

| [基準檢查規則](基準檢查規則.md) | 每項檢查（finding）的條件、使用的資料、常見原因與處理 | 使用者、開發者 | 新增或調整檢查時；和 `CATALOG` 的一致性由 `tests/docs.js` 檢查 |

| [多層網路架構圖 可行性評估](多層網路架構圖_可行性評估.md) | 規格書 v0.1 當時的可行性評估背景 | 想了解規格書修訂緣由的人 | 不再更新；狀態以規格書為準 |
