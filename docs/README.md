# 文件導覽

`docs/` 底下每份文件回答一個問題。一份資訊只寫在一處，其他文件用連結指過去，避免多份各自走樣（[ADR-016](架構決策/016-文件分工每個主題只有一個說明處.md)）。

## 分工原則

| 文件 | 回答 | 不寫 |
|---|---|---|
| [路線圖](路線圖.md) | 要做什麼、依什麼順序、做到什麼程度算完成 | 已實作的設計、決策的理由 |
| [架構決策（ADR）](架構決策/README.md) | 為什麼這樣決定：背景、選項與取捨 | 規格的全文（只連結到程式或文件） |
| [設計說明](設計說明.md) | 已做好的東西怎麼運作：模組、資料模型、推論規則、下游模組、檢視層架構 | 還沒做的計畫、版本紀錄 |
| [版本紀錄](版本紀錄.md) | 各版改了什麼 | 現在怎麼運作（連結到設計說明） |
| [多層網路架構圖 實作規格書](多層網路架構圖_實作規格書.md) | 多層架構圖的需求，與本工具的對應和狀態 | 實作細節（連結到設計說明） |

功能完成時，設計從路線圖移到設計說明，路線圖只在「已完成」留一句摘要；做法有取捨時另寫 ADR。

## 各份文件

| 文件 | 回答什麼問題 | 給誰看 | 什麼時候更新 |
|---|---|---|---|
| [路線圖](路線圖.md) | 接下來要做哪些功能、順序與依賴、負責的 agent、完成條件 | 使用者、主對話與各 agent | 排程改變、開始或完成一項時 |
| [架構決策](架構決策/README.md) | 影響整個專案的決策為什麼這樣做 | 要修改相關設計的人與 agent | 有新的決策（新增一份）、使用者做出決定、待辦完成（標「已處理」）、決策局部調整（加「修訂」） |
| [設計說明](設計說明.md) | 依「原則 → 上游（輸入、模型與推論 §5.3、檢查）→ 下游（比對、修正 patch、處理紀錄）→ 檢視層 → 附錄」排列；Snapshot 欄位在 §5.2；畫面操作暫存在 §12 | 開發者、要讀 Snapshot 的人 | 資料模型、推論規則、下游模組或檢視層架構改變時 |
| [版本紀錄](版本紀錄.md) | 各版的變更，新的在前 | 要知道升版改了什麼的人 | 每次升版（依 [ADR-005](架構決策/005-版本升級規則.md)） |
| [開發指南](開發指南.md) | 專案結構、指令、測試、擴充方式、外部資產、CI | 要修改程式的人 | 指令、測試種類或 CI 改變時 |
| [基準檢查規則](基準檢查規則.md) | 每項檢查（finding）的條件、使用的資料、常見原因與處理 | 使用者、開發者 | 新增或調整檢查時；和 `CATALOG` 的一致性由 `tests/docs.js` 檢查 |
| [收集清單與輸入格式](收集清單與輸入格式.md) | 每台設備要收集哪些指令、SSH 收集器的用法、`bundle-v1`／`files-v1` 格式、RouterOS 的限制 | 收集資料的人 | 收集指令、輸入格式或收集器改變時 |
| [命名規則](命名規則.md) | 命名 profile 的格式與能做的事（只能 canonicalize 或加註解） | 撰寫命名規則的人 | 命名 profile 的格式改變時 |
| [發布前檢查表](發布前檢查表.md) | 只有真實瀏覽器才測得到的項目：一頁的主清單（註明冒煙測試已涵蓋的部分），詳細步驟在附錄 | 發布前手動檢查的人 | 畫面行為或冒煙測試改變時 |
| [多層網路架構圖 實作規格書](多層網路架構圖_實作規格書.md) | 使用者的 L2／L3／L4 架構圖需求，每項的本工具對應與狀態 | 使用者 | 依使用者指示；實作完成時更新各項狀態 |
| [多層網路架構圖 可行性評估](多層網路架構圖_可行性評估.md) | 規格書 v0.1 當時的可行性評估背景 | 想了解規格書修訂緣由的人 | 不再更新；狀態以規格書為準 |

repo 根目錄的 [README](../README.md) 只有快速開始、功能一覽與文件連結；開發原則與 agent 分工見 [CLAUDE.md](../CLAUDE.md) 與 [.github/copilot-instructions.md](../.github/copilot-instructions.md)。
