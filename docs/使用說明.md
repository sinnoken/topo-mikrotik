# 使用說明

這份文件說明畫面怎麼操作，依頁首的流程步驟（① 輸入 ② 檢視 ③ 分診 ④ 修正 ⑤ 驗證）排列。畫面操作只寫在這裡（[ADR-016](架構決策/016-文件分工每個主題只有一個說明處.md)）；畫面背後的架構與資料的去向見[設計說明 §11](設計說明.md#11-檢視層架構)，每項檢查的判斷條件見[基準檢查規則](基準檢查規則.md)。

## 畫面配置

- **頁首**：流程步驟、「資料中心」、搜尋、路由追蹤與「清除」。
- **主畫面**分三塊：左邊是這一步的清單，中間是這一步的工作畫面，右邊是詳細資料。④ 修正與 ⑤ 驗證沒有左邊，中間佔滿全寬。
- 左右欄的邊緣可以拖曳調整寬度（最小 240px，中間至少 320px；雙擊還原）。寬度另外保存，不進基準，按「清除」也不受影響。
- **窄螢幕**分成三個工作區，依流程排列：這一步的清單、中間的工作畫面、詳細資料。按鈕的名稱跟著目前的一步，例如 ③ 是「檢查結果」「拓樸圖」「詳細資料」；④、⑤ 沒有清單的工作區。

## 流程步驟

| 步驟 | 左邊 | 中間 | 做什麼 |
|---|---|---|---|
| ① 輸入 | 資料中心蓋住整個主畫面 | | 讀入收集檔或工作包、看覆蓋率、匯出 |
| ② 檢視 | 清單（設備、介面、IP、網段、MAC、VLAN） | 拓樸圖或 L4 可達性 | 看網路的結構，切換設備、L2 埠、L3 子網與 L4 可達性 |
| ③ 分診 | 檢查結果 | 拓樸圖或 L4 可達性 | 決定每個問題要修、接受或標為誤報（開啟頁面時的預設） |
| ④ 修正 | | 修正計畫 | 選取檢查結果，產生並下載 `.rsc` |
| ⑤ 驗證 | | 本輪變化、處理紀錄、修復追蹤、收斂趨勢、比對 | 重新收集後確認哪些已修好、哪些回歸 |

- 每一步旁邊寫出目前的狀態：① 已收集的台數、② 拓樸圖的層級、③ 待處理的筆數、④ 已選的項目數、⑤ 處理紀錄是第幾輪（有回歸時另寫回歸數）。
- 按一步就切換，焦點移到這一步的標題。切換時拓樸圖的位置、縮放與選取都保留，不會重新排列。
- 還沒有基準時 ④、⑤ 不能用，按了會說明原因；清除基準時，停在 ④、⑤ 的畫面回到 ③。
- 在 ④、⑤ 點選檢查結果或比對的項目時，步驟不切換，詳情在右邊顯示。搜尋與路由追蹤會回到上一次看拓樸圖的 ② 或 ③。

## ① 輸入（資料中心）

按步驟列的「① 輸入」或頁首的「資料中心」開啟。這裡集中這一輪所有的輸入與輸出，全部在本機處理。

- **開關**：開啟後焦點移到標題。再按一次「資料中心」、按「回到「③ 分診」」（名稱是你原本所在的一步）或按 Esc 關閉，焦點回到開啟它的按鈕。建立基準或原文的對話框開著時，Esc 先關對話框；焦點在頁首的搜尋或路由追蹤時，Esc 由它們處理。資料中心開著時，Tab 不會移到被蓋住的畫面。從搜尋、摘要等處選取設備或檢查結果時，資料中心自動關閉。
- **這一輪的輸入**：每一列寫出項目、來源、狀態與操作。狀態一律有符號或文字（✓、!、✗、未載入），不只靠顏色。
  - 收集檔：來源名稱（由工作包帶回時註明）、已收集的台數與收集失敗的段數；「讀入收集檔…」開啟建立基準的對話框。
  - 上一輪的基準：已載入的舊基準與比對摘要（新增、移除、變更），或由工作包帶回、等這一輪的收集檔讀入後比對；「載入舊基準（JSON）…」。
  - 處理紀錄：目前是第幾輪、共幾輪幾項，或停用的原因；「讀入處理紀錄…」。
  - 命名規則：名稱與版本、是否已套用；「變更…」開啟建立基準的對話框選擇。
  - 建立選項 expectedData：幾類設備、是否使用（會改變基準鍵），目前只會由工作包帶回。
  - 預期資料（`ssot-expected/1`）：檔名與比對結果；「載入預期資料（JSON）…」。
  - 覆蓋率：已收集／全部的台數，以及只被鄰居發現的網路設備（C01）；「每台設備的收集情形」捲到下方的覆蓋率；有 C01 時可「匯出 devices.csv 草稿」。
- **覆蓋率**：每台設備收集了哪些資料。「有缺漏」包括缺少應收集的資料與有指令收集失敗的設備，失敗的指令與原因可以開啟原文。點一列在右邊看設備的詳細資料（資料中心會關閉）。基準摘要的「收集缺漏」也會開到這裡。
- **這一輪的輸出**：上方是工作包的內容與「匯出本輪工作包（ZIP）」，下方是五張卡片：
  - 給下一輪的自己：基準 JSON、處理紀錄 JSON。
  - 給設備：開啟修正計畫（④）；修正計畫有選取的項目時，註明會放進工作包。本工具只產生文字，不會連線設備。
  - 給報告或紀錄：檢查結果 Markdown、CSV（含處理狀態，不受 ③ 檢查結果的篩選影響）、「依設備排序」（工作包裡的報表也依這個設定）、拓樸 PNG。報表的內容見下方的「[儲存與匯出](#儲存與匯出)」。
  - 給收集器：devices.csv 草稿；有收集失敗時，列出只重收失敗指令的 `tools/collect.sh … --retry-failed` 指令。
  - 給之後的比對：由目前的基準產生預期資料。
- **下載工作包**：每個項目一個勾選框。收集檔與基準一定要放（勾選且不能取消）；基準用了命名規則或 expectedData 時，它們也一定要放。處理紀錄、預期資料、報表、修正 patch 可以取消；目前沒有的資料（例如處理紀錄停用、修正計畫沒有選取）不能勾選，並說明原因。收集檔可能含有設備機密，請自行保管。建立失敗時列出全部問題，不會下載。
- **讀入工作包**：按「讀入工作包…」選擇 ZIP。
  - 格式錯誤（例如檔案不完整、CRC 不符、收集檔順序不同）時列出全部問題與警告，目前的資料不變。
  - 讀入成功時，先列出工作包的版本、建立時間、檔案數與警告，再勾選要帶回的內容：上一輪的基準（以工作包的收集檔重新建立並核對，取代目前的基準）、處理紀錄（整份取代）、預期資料（取代）；建立選項 expectedData 在重建時一定使用。
  - 命名規則選單預設是工作包附的，也可以換成目前清單中的，或不套用；和工作包不同時會提示：基準鍵會不同，處理紀錄會當成新的一輪。
  - 目前的處理紀錄有工作包沒有的內容（項目、內容不同或輪次）時，寫出會遺失什麼，提供「先匯出目前的處理紀錄」，要勾選「我了解，取代目前的處理紀錄」才會帶回。
  - 重建核對沒有通過時列出問題，什麼都不帶回。帶回後列出帶回的內容與警告。
  - 建立與讀取期間顯示忙碌提示並停用操作，大型資料可能要數秒，完成前畫面會暫停回應。帶回時重建基準的期間顯示重建進度，畫面不會停住。
- **接著做下一輪**：帶回上一輪的工作包後，再按「讀入收集檔…」讀入這一輪的收集檔。建立基準時會自動以工作包的基準當成上一輪比對，並推進處理紀錄。
- **處理紀錄的匯出與匯入**：「處理紀錄 JSON」匯出；「讀入處理紀錄…」匯入。匯入會先檢查格式，不正確時列出全部錯誤、目前的處理紀錄不變；正確時確認後以匯入的內容**整份覆蓋**目前的處理紀錄（不合併），建議覆蓋前先匯出。處理紀錄也會放進工作包。資料格式與狀態規則見[設計說明 §10](設計說明.md#10-處理紀錄ssot-ledger1)。
- **建立基準的對話框**：可以貼上或選擇收集檔、載入範例資料、選擇命名規則。這一輪有建立選項 expectedData（由工作包帶回）時，另有「使用建立選項 expectedData」的勾選框，預設勾選並註明類別數與「會改變基準鍵」；取消勾選時這次建立不使用。還沒有基準時，歡迎畫面的「建立基準…」也開啟同一個對話框。

## ② 檢視

左邊是清單，中間是拓樸圖。

### 清單

- 設備、介面、IP、網段、MAC、VLAN 六份完整清單，可以文字篩選；IP 已去重複，MAC 清單可以篩「缺 IP」。
- 網段是由設備自有介面位址推導的直連網段，列出設定的設備或介面，以及落在網段內的 IP 數。
- 設備清單另有「終端」分類：一般的非 Wi-Fi 介面要恰好學到一個 MAC，而且沒有 LLDP／CDP 介面鄰接。
- Wi-Fi 介面本身不算終端介面，但每個 Wi-Fi MAC 的觀察位置仍列入終端清單，而且不參與 A02（MAC 可能因漫遊出現在多個 AP）。
- 同一個 MAC 的一般終端位置，只在 VLAN 相同或兩端都沒有記錄 VLAN 時比較；同一個 VLAN ID 分成多個不相連的區塊時（例如各站點重用），只比較同一塊內的位置。區塊是依鏈路證據的推論，所以 A02 是待核實的警告。
- 只有 MNDP 廣播網域可達的不算直連鄰接，不計入總覽的設備數。

### 拓樸圖

拓樸圖在 ② 和 ③ 都看得到。

- 版面預設為「分層（ELK）」：先以快速版面出圖，再於背景用 ELK 做多輪交叉最小化後替換。網路設備超過 1500 台或計算失敗時，維持快速版面並提示原因；可以在工具列切換「快速（內建）」。
- 只畫 L2 鄰接；同兩台設備之間有多條鏈路時合併成一條，畫成中間有細縫的雙線。
- 只有 MNDP 的設備對不畫線（MNDP 只證明同一 L2 廣播網域可達，不代表直連），但仍列在設備的鄰居表與鏈路詳情。OSPF 鄰接也不畫成拓樸的連線。
- 沒有 LLDP 的設備（例如 SwOS 的 CSS106、CSS610）依 MAC 表、點對點網段推定「推論鏈路」，以長虛線表示，點選可看依據與信心。接在這類交換器底下的終端，依上一跳的 MAC 表推定位置（埠不明），畫在該交換器下。
- 連線兩端的埠名在放大時顯示；滑過連線或節點（以及選取連線）時，不受縮放與重疊限制，一定顯示。
- 符合終端條件的位置，以「未知對端」節點畫在所屬設備下方（可以收合、可以關閉）。Wi-Fi MAC 觀察位置也保留圖面提示，多個 MAC 以菱形呈現。
  - 點節點或群組：右邊顯示每個埠的 MAC、IP、廠商、VLAN；點一列跳到那個介面。設備頁也有同樣的清單。
  - 搜尋 MAC 或 IP 時，圖上會標出它所在的那個終端；點檢查結果 A03 會顯示該設備的終端清單。
  - 工具列的「未知對端」可以整個關閉。位置會和其他節點一起保存。
- 圖例（左下，預設收合）分「設備／終端／連線／連線註記／標示」五類，和圖上一致：
  - 嚴重度除了顏色還有外形：錯誤是方形、警告是三角形，標在設備右上角（主機與終端也有）與有問題的連線中點。
  - 連線依速率分色，線寬隨速率遞增（1G → 10G → 40G，聚合最粗）；1G 是依介面名稱推估的分類，不代表實際協商速率。
  - 單側觀察是點線、推論鏈路是長虛線，顏色仍依連線類別。連到 Wi-Fi 與容器 veth 介面終端的連線各有專用線型。
  - 終端依廠商上色，只取終端數量最多的前 8 個廠商，其餘與不明廠商歸「其他」的中性色。
  - 「標示」列出嚴重度的外形，以及選取（藍色粗環）、滑過（深色細環，鍵盤 N 移到的設備也是）、搜尋結果與路由追蹤（含箭頭）的樣式。
  - L2、L3 另有：埠（L2）、子網（L3）、路由（L3）、網段重疊（L3），以及 VLAN 篩選的四種線型。
- 鍵盤：點一下拓樸圖（或用 Tab 移到它）取得焦點後可以操作；移到的設備會讀給螢幕閱讀器。L2 埠圖與 L3 子網圖也一樣，N／Shift+N 輪流移到節點。

  | 按鍵 | 動作 |
  |---|---|
  | N／Shift+N | 依畫面位置（由上而下、由左而右）移到下一台／上一台設備，移出畫面時自動平移 |
  | Enter／空白鍵 | 選取 N 移到的設備並開啟詳情 |
  | Shift+Enter | 聚焦到 N 移到的設備（同雙擊） |
  | Esc | 取消選取 |
  | 方向鍵 | 平移（按住 Shift 移動較多） |
  | +／- | 以畫面中央為中心放大／縮小 |
  | 0 | 全圖 |

- 觸控：拖曳空白處平移、拖曳節點移動位置；點一下選取，點兩下等同雙擊（聚焦，或展開「終端 ×N」群組）。觸控的命中範圍比滑鼠大。
- 系統設定為減少動態效果時，不播轉場動畫，「力導向排列」直接顯示結果。

### 層級：設備、L2 埠、L3 子網、L4 可達性

- **切換**：工具列的「設備」「L2 埠」「L3 子網」「L4 可達性」四種。這是一組選項按鈕：Tab 移到選取的那一個，←、→（或 ↑、↓）、Home、End 切換。② 的步驟狀態寫出目前的層級。L4 不是圖，操作見下方「[L4 可達性](#l4-可達性)」。
- 切換時選取保留，在新的一層重新標示；各層的平移與縮放分開保存。「重新排列」只重排目前的層級。「未知對端」「分群」只在設備圖顯示。
- **L2 埠圖**：設備是方框，埠是框邊上的小方塊（聚合埠較寬，推論鏈路未收集端的未知埠是虛線），線接在埠上；只畫 LLDP／CDP 介面鄰接與推論鏈路。
  - 選項：「展開聚合」（成員各自畫成一個埠；預設收合）、「全部的埠」（也畫沒有連線的實體、聚合與無線介面）、範圍（「整張圖」或「選取的設備與鄰居」）。
  - **焦點模式**：範圍是「選取的設備與鄰居」時，只畫一台設備與它的鄰居。雙擊鄰居的設備框（或 N 移到它後按 Shift+Enter）改以它為中心；選取不在圖上的設備時，也會改看那一台。設備超過 300 台時只能用焦點模式，「整張圖」不能選，圖的上方說明原因；沒有選取設備時，先看連線最多的路由器、防火牆或交換器。
  - 點設備框開啟設備詳情；點埠開啟介面詳情（未知埠開啟設備詳情）；點連線時，只有一條鏈路開啟鏈路詳情，多條時開啟這對設備的鏈路清單。
- **L3 子網圖**：子網是圓角長條，設備是節點，位址把設備接到子網；鄰居回報的位址與管理 IP 是推論，用較淡的線型。接到兩個以上子網、有路由表或是路由器／防火牆的設備是路由設備（推論）。
  - 「顯示路由」：以虛線箭頭畫出靜態路由與預設路由，從路由所在的設備指到目的網段；只由路由得知的網段用虛線外框。
  - 互相包含的網段之間畫警告色的虛線，中點有警告外形；子網下方另標「重疊網段」「重複 IP」。
  - 點子網、重疊線或路由開啟子網詳情；點設備開啟設備詳情；點位址的連線開啟那個介面。
  - **子網詳情**：網段、VLAN、路由設備、閘道（DHCP 網路）、VRF（M3 之前寫「不分 VRF」）；位址（IP、設備或介面、依據與是否推論、來源行，重複的 IP 另外標示）；接在這裡的設備；重疊網段（包含或被包含）；重複 IP；路由到這個網段的路由（設備、協定、下一跳、經由的網段）；以及相關的檢查結果。
- 「匯出 PNG」畫的是目前的層級，有畫布底色、不是透明背景；檔名是 `topology.png`、`topology-l2.png` 或 `topology-l3.png`。L4 可達性沒有 PNG，改用 L4 畫面的「下載 CSV」。

### VLAN 篩選

工具列的「VLAN：不篩選」選單，或在詳情選一個 VLAN。在設備圖與 L2 埠圖標出承載這個 VLAN 的鏈路，L3 標出這個 VLAN 的子網。

| 線型 | 意思 |
|---|---|
| 實線 | 承載：兩端都帶這個 VLAN |
| 長虛線 | 推論承載：推論鏈路，已收集的各端都帶 |
| 錯誤色實線加垂直短刻度，中點有錯誤外形（方形） | 只有一端帶：兩端都有 VLAN 資料，只有一端帶（V01） |
| 淡色點線 | 一端未知：只有一端可確認（對端沒有收集、沒有 VLAN 資料、只有單側觀察，或在沒開 vlan-filtering 的 bridge 上），推論 |

- 滑過連線時，提示寫出承載狀態與原因；VLAN 詳情另列「只有一端可確認的鏈路（推論）」與原因。
- 篩選會一直保留，直到在選單選「不篩選」；選設備、鏈路等其他東西時，沒有自己的標示的地方仍標出這個 VLAN。（2.10.0 以前，選了別的東西篩選就會消失。）
- 同一個 VLAN ID 分成幾個不相連的區塊時（例如各站點重用），詳情會列出各區塊，可以只看其中一塊。區塊是依鏈路證據的推論。

### L4 可達性

在工具列選「L4 可達性」（② 和 ③ 都可以）。中間換成 zone 矩陣與可達性查詢，拓樸圖暫時收起，回到其他層級時照原樣還原。這裡的結果全部是依基準的路由與防火牆規則**推論**出來的，不寫進基準，判斷規則見[設計說明 §5.3「L4 可達性與 zone」](設計說明.md#l4-可達性與-zone2110-新增)。

- **判斷的前提**（最上方，標「推論」）：只判斷新連線（回程由連線追蹤放行）、只套用 raw、nat、filter（不含 mangle、bridge filter 與主機本身的防火牆）、只算 IPv4 與 main 路由表、address-list 的內容一律無法判斷等。看結果前先讀這幾條。
- **zone 矩陣（L0）**：列是來源 zone，欄是目的 zone。
  - 每一格寫出狀態的符號與文字，不只靠顏色：✓ 全通、✕ 全擋、◐ 部分、? 不明、– 沒有組合（斜線底紋）。數字是「允許／總數」：每個 zone 取代表位址，代表位址 × 目的 × 服務各算一次。
  - 「≠ 異質」表示同一個 zone 的成員結果不一致：zone 可能分得不對，或規則只放行部分位址。對角線（來源與目的是同一個 zone）是虛線外框，zone 內的流量主要受主機防火牆影響，不在範圍內。
  - 圖例在矩陣上方；狀態列寫出 zone 數、代表位址數、dst-nat 入口數、判斷次數與計算時間（或「使用快取」）。
  - **服務**：選單可以選「全部服務」或單一服務（例如 `tcp/443`）；選項是預設的服務，加上 dst-nat 規則的目的埠。
  - **矩陣／表格**：表格檢視每一格一列，可以排序，點一列往下看。zone 超過 60 個時只能用表格；表格最多列 3000 格，完整內容用「下載 CSV」。
  - **下載 CSV**：目前服務的矩陣，每一格一列（欄位見[設計說明 §11.5](設計說明.md#115-匯出)）。
  - 第一次開矩陣時，大型網路要數秒，期間顯示「計算 zone 矩陣中…」的忙碌提示；同一份基準再開，或切回算過的服務時，直接使用快取。
- **滑過格子**（或用鍵盤移到格子）時，提示寫出允許、拒絕、無法判斷的筆數、是否異質、代表規則與無法判斷的原因。
- **鍵盤**：L4 畫面在工具列之後，Tab 先經過工具列再進入畫面。矩陣只有一個 Tab 停點（目前的格子），用方向鍵移動，Home／End 到這一列的頭尾，Ctrl+Home／Ctrl+End 到整個矩陣的頭尾；Enter 或空白鍵往下看，Esc 收起提示。開啟下鑽時焦點移到下鑽的標題，按「關閉下鑽」後回到原來的格子。
- **下鑽**（點格子或按 Enter）：上方寫出這一格的狀態、筆數與目前的服務，以及無法判斷的原因。
  - **L1：位址組**：每一列是一個目的與一組結果相同的來源代表，寫出各服務的結果、狀態與閘道或入口。目的是 dst-nat 的入口時標出改寫後的位址。來源有多個時寫「… 等 N 個」，滑過看每個位址與它是 ARP 看到的還是推算的。同一格同時有拒絕和其他結果時，全部拒絕的組預設收起，可以按「顯示全部拒絕的組」展開。點一列看第一個服務的逐跳路徑，點某個服務的結果看那個服務的。
  - **L2：牽涉的規則**：決定結果的規則、chain 結尾的預設與路由，以及條件無法判斷的規則，各有允許、拒絕、無法判斷的筆數與服務。點規則在右邊開啟規則詳情（命中次數與 L4 影響，見[右側的詳細資料](#右側的詳細資料)的「防火牆」）。
  - **L3：逐跳路徑**：
    - 最上面是結論（允許、拒絕、無法判斷），有 NAT 時另寫 NAT 之後的目的。
    - 「起點」說明封包從哪裡進入：來源網段的閘道（依 DHCP 網路、網段上有路由表的設備或已收集的設備）、網路設備自己送出，或來源與目的在同一個網段。
    - 「決定結果」列出決定結果的規則或路由（例如沒有符合的路由、黑洞路由）。無法判斷時列出原因（例如規則的條件無法判斷、設備沒有收集），其他結果的同類說明列在「附註」。
    - 每條路徑逐跳列出：設備與 chain、這一跳的結果、位址（被 NAT 改寫時寫出改寫後的位址）、入與出的介面、使用的路由，以及各關（`raw prerouting`、`nat dstnat`、`filter forward` 等）由哪條規則決定、NAT 前後的位址、設備的服務是否接受。有 ECMP 或多個閘道時，每條路徑各列一次。最後一行是路徑的結束原因。
    - 「這次查詢的前提」預設收合。
- **可達性查詢**：輸入來源 IP、目的 IP、協定（tcp、udp、icmp）與目的埠，按「查詢」或在欄位中按 Enter。icmp 不用填埠（欄位停用）；tcp、udp 一定要填。結果以同一個 L3 畫面顯示在矩陣下方，不屬於任何格子；位址不是有效的 IPv4 或參數不對時，寫出原因。
- **zone 的依據**（最下方，標「推論」）：每個 zone 的名稱、來源（命名規則、interface list、VLAN、網段）、依據、網段與設備數；名稱旁的「推論」標示這個 zone 是推論來的。展開「每個網段的依據」可以看每個網段用了哪個來源，以及其他來源會得到的 zone，用來檢查分得合不合理。
  - 命名規則有 `zones` 段時，以命名規則的標籤為準（不是推論）。命名規則和建立基準時用的不是同一份（例如改了 `zones` 卻沒改 version，或基準是 2.11.0 以前建立的）時，不套用 `zones` 段，在狀態列與這裡寫出原因；要用同一份命名規則重新建立基準（[命名規則「zones」](命名規則.md#zones選用2110-新增)）。
- 搜尋與路由追蹤是「在圖上定位」，在 L4 時會改回設備圖。

<a id="step-triage"></a>

## ③ 分診

左邊是檢查結果，中間是拓樸圖，右邊是證據與處理建議。開啟頁面時預設在這一步。

- 點任一筆，圖上會定位並標紅。沒有發現的規則列在下方，分成「通過」與「沒有資料可檢查」（預設收合）；這些規則也可以展開「常見原因與處理」，看處理建議。
- 每筆旁邊的「處理」可以變更它在處理紀錄中的狀態：待處理、已排程修復、可接受（豁免）、誤報、已修好，並可填備註。
  - 選單只列目前狀態可以改成的狀態。
  - 選「可接受」要填原因與到期日（預設約半年後）；到期後，下一次建立基準時自動改回待處理。
  - 「已修好」只能用在這一筆已不在目前基準時；平常是重新收集、建立基準後自動判定。修好後又出現的標為「回歸」。
  - 不合法的變更會在欄位下方說明原因。
- 已處理（已排程修復、可接受、誤報、已修好）的項目依狀態各列一組（預設收合），顯示狀態、時間、豁免原因與備註，不計入上方與頂端摘要的筆數（摘要會註明另有幾項已處理）。有標為誤報的規則時，另列「誤報率最高的規則」。
- 處理紀錄只存在這個瀏覽器，不改變基準；按「清除」不會清掉它，之後重新建立同一份網路的基準時仍然有效。舊版的「確認」紀錄在第一次建立或還原基準時自動轉換成處理紀錄（未分類的視為可接受），提示列會顯示轉換的筆數。
- 可以切換「依規則」或「依設備」分組；依設備時，不屬於任何設備的檢查結果（例如沒有設備標頭的 I01）排在最後一組。
- **只看新出現的**：在 ⑤ 驗證的比對或資料中心載入舊基準後，可以只列出舊基準沒有的檢查結果；沒有按下時，新出現的那幾筆標「新出現」。兩份基準的程式版本不同時，旁邊提示新出現的可能只是新版才有的檢查。沒有載入舊基準（或比對失敗）時這個選項不能用；建立或載入新的基準後，要重新載入舊基準。
- 中間的工具列也可以切到「[L4 可達性](#l4-可達性)」，看防火牆的檢查結果實際影響哪些 zone 之間的連線。點防火牆規則的檢查結果時，右邊的規則詳情另有命中次數與「計算 L4 影響」（見[右側的詳細資料](#右側的詳細資料)的「防火牆」）。
- 「匯出報表…」開啟資料中心的報表；「修正計畫…」到 ④ 修正。

<a id="step-fix"></a>

## ④ 修正

中間是修正計畫，佔滿全寬。從步驟列的 ④、③ 的「修正計畫…」，或防火牆畫面的「在修正計畫中開啟」進來。**本工具只產生文字，不會連線或改動任何設備**；套用前請逐行審查，自行以 `/import` 執行，之後重新收集、建立基準確認結果。

- **要修正哪些**：依規則（可產生指令的規則排前面，點一下選取或取消這條規則的全部）、依設備（「加入這台的全部」）、展開規則逐筆勾選，或「全部清除」。同一條規則、同一組設備有多個檢查項目時（例如 A12 的 DNS 與 NTP），各自一列，可以分別勾選。換了基準時選取會清空。
- **計畫**：依設備列出每一項的修改前（基準的原文，可以開啟原始輸出）與修改後（套用指令）、說明與風險。每台設備可以切換檢視套用、回復、驗證三個 `.rsc`，可以複製或下載；多台設備時可以逐檔下載全部，另附一份總表（Markdown），或只下載總表。沒有產生指令的項目依原因分組列出。要一個檔案帶走時，可以在資料中心匯出工作包（含這裡選取的 patch 與總表）。
- 目前 F01、F02、F06 能產生停用規則的指令，A12（DNS／NTP 伺服器）可以在「需要選擇的項目」選擇要採用的值；其他檢查結果，以及 `find` 無法只找到一條規則的情況，列出沒有產生指令的原因。
- **需要選擇的項目**（A12）：每筆列出選項：改成多數設備的值、改成某一組設備的值，或「不修改」。
  - 多數的選項標示「推論」，並寫出「N 台中 M 台」；預設採用它，可以改選。
  - 沒有多數時，要先選擇才會產生指令。
  - 選了某一組後，其他組的設備會產生指令；每一項顯示修改前 → 修改後（例如「10.1.10.2 → time.cloudflare.com」）與警告，並標示「依選擇」。
  - 選「不修改」時，填原因與到期日，按「標為可接受」寫進處理紀錄。
  - 選項是一組選項按鈕，可以用鍵盤切換；切換後焦點留在剛選的選項。
  - 下載的總表多一段「需要選擇的項目」，列出每筆目前的選擇，以及是預設（多數決，推論）還是使用者選擇。
- 畫面夠寬時（約 880px 以上），左邊是「要修正哪些」（捲動時固定），右邊是計畫；較窄時上下排。修正的規則與 `.rsc` 的寫法見[設計說明 §9](設計說明.md#9-修正-patchssot-patch1)。

<a id="step-verify"></a>

## ⑤ 驗證

中間佔滿全寬，重新收集、建立基準後，在這裡確認哪些已修好、哪些回歸。畫面夠寬時，左欄是本輪變化與處理紀錄（捲動時固定），右欄是修復追蹤、收斂趨勢與比對。

- **本輪變化**：新出現、已修好、回歸（修好後又出現）、豁免到期，以及因收集失敗而無法判斷的項目（所屬設備有收集失敗或沒有收集時，消失的問題不判定為已修好）。目前基準有這一筆時，點一下定位。和上一輪的基準版本不同時，提示新出現的可能來自新版檢查。同一份基準已經推進過（例如重新開啟頁面）時，說明沒有新的變化。
- **處理紀錄**：各狀態的筆數；豁免沒寫原因時提醒補上。「在資料中心匯出或匯入…」開啟資料中心的處理紀錄。
- **修復追蹤**：已排程修復的項目（標示目前基準仍有或沒有），以及累計已修好的項目；上方列出已排程修復、目前基準仍有、累計已修好三個數字。
- **收斂趨勢**：每建立一份新的基準算一輪。只有一輪時列出目前的數字；兩輪以上畫出待處理、回歸、已豁免的筆數，以及覆蓋率與未知對端的變化。
  - 三條線以圓形、方形、三角形區分，圖例與提示也畫出同樣的外形；線尾寫出名稱與數值。
  - 滑過圖，或用 Tab 移到圖上（每張圖停一次）再以 ←、→、Home、End 切換輪次，可以看每一輪的數值與建立時間。
  - 「表格檢視」列出同樣的數字。
- **比對**：
  - **預期資料比對**：載入「預期應該長怎樣」的 JSON（格式 `ssot-expected/1`，範例見 [`samples/expected-sample.json`](../samples/expected-sample.json)），和目前的基準比對；也可以在資料中心載入。預期資料是這一輪的輸入：建立或載入新的基準後保留，自動和新的基準重新比對。由目前的基準產生預期資料的按鈕在資料中心的「這一輪的輸出」。
  - **與舊基準比對**：載入之前用資料中心的「基準 JSON」存下的基準，依設備、鏈路、VLAN、IP、防火牆、檢查結果分組列出新增、移除與變更；防火牆規則讓 WAN 多出可連入點的標示為「新暴露」，可以單獨篩選。兩份基準的程式版本或命名規則不同時，比對結果上方會提醒：新版才有的檢查會顯示為新出現，名稱與分群可能因命名規則而不同，這些差異不代表網路改變。
  - 點一列在右邊開啟那個項目。比對結果不會儲存，兩種比對都只讀取基準，不會修改它。

## 右側的詳細資料

- 鄰居（含類別與 LLDP／MNDP／CDP 協定）、OSPF L3 鄰接、介面（埠模式、PVID、untagged／tagged VLAN、所屬聚合／bridge）、VLAN、MAC、路由表。
- 介面詳情列出 bridge 的 vlan-filtering（開或關；關時標示「VLAN 原樣轉送，不看也不改標籤」）。介面在沒開 vlan-filtering 的 bridge 上時，PVID、frame-types、ingress-filtering 旁邊標示「沒有作用（bridge 沒開 vlan-filtering）」（推論，依 RouterOS 手冊）。
- 設備的「收集到的原始輸出」列出每個指令的收集時間（UTC，收集器記錄的）與收集失敗；有失敗時預設展開。已解析的區塊中有認不得的行（I03）時，解析器欄另標「部分無法辨識（N 行）」，點一下開啟第一行。
- 沒有選取任何東西時，右邊是基準的總覽：建立時間、輸入指紋、基準鍵（處理紀錄以它判斷是不是同一輪）、命名規則與各項筆數。
- **防火牆**：設備詳情的「防火牆」摘要規則數、有問題的規則數與 WAN 判斷狀態（「已找到 WAN 介面（推論）」「沒有 WAN interface list（推論）」或「WAN interface list 沒有成員（推論）」）；點「查看防火牆規則與服務」進入防火牆畫面，依位址族、表、chain 列出規則與相關的檢查結果，另列 WAN／LAN 判斷（推論）、`/ip service` 與 interface list。點選 F01–F07 的檢查結果時，會直接開啟防火牆畫面並定位到那條規則或服務。
- **命中次數**：防火牆畫面的規則表有「命中」欄（封包數，加千分位；滑過看位元組數）。定位到一條規則時，另列「命中次數」：封包、位元組與來源行。
  - 命中次數是收集當下的累積值，設備重開或 reset-counters 後從 0 重新計算。**0 只代表到收集時為止沒有比對到**，不代表規則沒用：備援、少見的流量或剛加上的規則都可能是 0。
  - 沒有數字時寫出原因：沒有收集這個表的 `print stats`、有 `print stats` 但這台沒有 export，或命中次數對不上 export 的規則。對不上時整個表都不採用，寫出第一個不符的地方（例如列數不同、某一列的 chain 或動作不同），旁邊的 F09 可以點開（[F09](基準檢查規則.md#f09)）。
- **L4 影響（推論）**：定位到一條規則時，按「計算 L4 影響」才計算（第一次要先算 zone 矩陣，大型網路約需數秒）。結果列出這條規則牽涉的 zone 對（決定結果、條件無法判斷、只是經過的筆數與服務）、是否被遮蔽（F01）或重複（F02），以及**停用這條規則後**結果改變的筆數（例如 allow→deny）與路徑。算過的結果保留到換基準為止。命名規則有 `zones` 段時，用和 L4 畫面相同的 zone。
- **修正（停用規則）**：防火牆畫面的「修正（停用規則）」列出這台設備（或定位到的那條規則）可以修正的檢查結果。F01、F02、F06 產生停用指令，附 find 的依據與風險，可以按「複製」；F03 要選擇處理方式，以及 `find` 無法只找到一條規則（例如 F02 的兩條規則完全相同）時，列出沒有產生指令的原因。指令以 comment 或規則的比對條件 `find`，不用規則編號。「在修正計畫中開啟」可以取得含前置檢查、回復與驗證的完整 `.rsc`。這只是文字，本工具不會連線或寫回設備。
- 跨設備一致性的檢查結果，詳情會列出「依多數決推定偏離」的設備（推論）。
- 同一條規則、同一組設備可能有多筆檢查結果時，詳情會在標題旁標示「檢查項目」，例如 A12 的「DNS 伺服器」與「NTP 伺服器」。
- 詳情裡的每筆檢查結果都有預設收合的「常見原因與處理」，內容和[基準檢查規則](基準檢查規則.md)各章的「常見原因」「處理」一致；RouterOS 指令與欄位以等寬字型顯示。
- 點 A03（未知對端）會開啟該設備的終端 MAC 位置畫面，終端埠清單前面列出這台設備的 A03 與它的常見原因與處理。
- 每筆都能開啟原文並標示行號；VLAN、鄰居、OSPF、路由與原始輸出可以按需要展開。

## 搜尋與路由追蹤

- 上方的搜尋可以直接輸入設備名、MAC、IP、VLAN ID 或介面描述。搜尋是「在圖上定位」：在 ④、⑤ 時會回到 ② 或 ③ 的拓樸圖。
- **路由追蹤**：輸入來源與目的 IP，逐跳顯示（含 ECMP），同時列出回程並標示非對稱路徑，遇到黑洞路由會停下。路徑畫在拓樸圖上。

## 基準摘要

建立基準後，頂端摘要顯示檢查規則發現的錯誤／警告（不含已處理的項目）與收集缺漏（含收集失敗）。「查看錯誤／警告」到 ③ 分診，「收集缺漏」開啟資料中心的覆蓋率，另有搜尋與路由追蹤的入口。依處理紀錄有回歸、因收集失敗而無法判斷，或豁免到期的項目時，摘要另有對應的提示，點一下到 ⑤ 驗證的本輪變化。每項規則的判斷條件與處理建議見[基準檢查規則](基準檢查規則.md)。

這些是該份 Snapshot 的檢查結果與收集完整度，**不代表即時網路健康狀態**。

## 儲存與匯出

- 基準存在這個瀏覽器（IndexedDB），下次開啟自動還原；程式更新後若基準格式不同，會用儲存的輸入重新建立。
- 按「清除」只清除本工具儲存的基準與輸入（含載入的預期資料）；處理紀錄、版面寬度等設定不受影響。處理紀錄只存在這個瀏覽器，請定期在資料中心匯出，或匯出工作包保存。
- 所有匯出都在資料中心（[① 輸入](#step-input)）；拓樸圖的工具列另有「匯出 PNG」。
  - 基準 JSON：目前的基準原樣下載，不改寫，可以留作之後「與舊基準比對」的舊基準。
  - CSV：UTF-8 含 BOM，Excel 可以直接開啟。除了檢查結果本身，另有處理紀錄的狀態、時間、備註、豁免原因與到期日、所屬設備與處理建議（照規則目錄原文，指令保留反引號）。舊版的確認欄位（`acknowledged`、`ack_kind`、`ack_note`）保留在原位置，改由處理紀錄對應。常見原因不放進 CSV，因為同一段文字會在每一列重複。欄位見[設計說明 §11.5](設計說明.md#115-匯出)。
  - Markdown：依規則分組時，每條規則先列處理建議與逐條的常見原因，指令寫成行內程式碼；依設備分組時，處理建議與常見原因集中在報表最後的「附錄：處理建議與常見原因」，每條規則只列一次。
  - 按下「依設備排序」後，CSV 依設備排序、Markdown 依設備分組。
  - devices.csv 草稿：由只被鄰居發現的網路設備（C01）產生 [SSH 批次收集](收集清單與輸入格式.md#0-批次-ssh-收集器wsllinux)用的設備清單。`user` 欄是佔位值 `CHANGE_ME`，使用前要改成實際的帳號；沒有位址或名稱不合規則等不能直接使用的設備寫成註解列，修正後移除開頭的 `#`。
  - 檔名含建立時間與設備數，例如 `findings-20260101T000000Z-42dev.csv`；工作包是 `workpack-<時間>-<N>dev.zip`。
