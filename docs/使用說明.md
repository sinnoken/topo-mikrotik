# 使用說明

這份文件說明畫面怎麼操作，依頁首的流程步驟（① 輸入 ② 檢視 ③ 分診 ④ 修正 ⑤ 驗證）排列。畫面操作只寫在這裡（[ADR-016](架構決策/016-文件分工每個主題只有一個說明處.md)）；畫面背後的架構與資料的去向見[設計說明 §11](設計說明.md#11-檢視層架構)，每項檢查的判斷條件見[基準檢查規則](基準檢查規則.md)。

## 畫面配置

- **頁首**：流程步驟、搜尋、「資料中心」與「⋯」（更多操作：「路由追蹤…」「匯出 PNG」「清除基準…」，最下方是程式版本）。沒有摘要列與頁尾，基準的摘要在右邊的[基準狀態卡](#右側的詳細資料)。
  - 「⋯」與工具列的「版面 ▾」「顯示 ▾」是下拉選單：開啟後焦點在第一個項目（在按鈕上按 ↑ 開啟時在最後一個），↑、↓、Home、End 移動；Esc 關閉並回到按鈕，按 Tab 或點選單外面也會關閉。
- **主畫面**分三塊：左邊是這一步的清單，中間是這一步的工作畫面，右邊是詳細資料。④ 修正與 ⑤ 驗證沒有左邊，中間佔滿全寬。
- 左右欄的邊緣可以拖曳調整寬度（最小 240px，中間至少 320px；雙擊還原）。寬度另外保存，不進基準，清除基準也不受影響。
- **通知**（例如設備圖分層版面的進度、還原基準）顯示在拓樸圖的下方中央，不遮工具列，暫時性的通知數秒後淡出。L2 埠圖與 L3 網段圖的分層版面計算中、未套用的原因寫在圖上方的說明裡，不另外通知。拓樸圖右下的操作提示只在這次開啟頁面第一次看到圖時顯示，約 6 秒後淡出；觸控裝置上改寫成雙指縮放、拖曳移動、點一下、點兩下（歡迎畫面的步驟說明也改用觸控的說法）。
- **窄螢幕**（寬 900px 以下）：
  - 頁首只有流程步驟一列（五步等寬）。下面是工作區的按鈕，右端是搜尋圖示與「⋯」：點搜尋圖示（或按 /）展開成輸入框，蓋住這一列。窄螢幕沒有「資料中心」按鈕，從「① 輸入」進入；資料中心開著時不顯示搜尋與「⋯」。觸控裝置上的按鈕與輸入框至少 44px 高。
  - 分成三個工作區，依流程排列：這一步的清單、中間的工作畫面、詳細資料。按鈕的名稱跟著目前的一步，例如 ③ 是「檢查結果」「拓樸圖」「詳細資料」；④、⑤ 沒有清單的工作區。
  - **詳情抽屜**：在拓樸圖上選取時，詳細資料以底部抽屜疊在圖的下方（半高約 40%），圖仍看得到、可以操作，被抽屜擋住的節點會平移到看得到的地方。抽屜上方的把手可以拖曳調整高度（拖到很低時收起、拖到很高時展開成全高），點一下把手或按「展開」「半高」切換全高與半高；按「收起」或 Esc 收起（選取不變）。從清單工作區點選時，會回到拓樸圖並開啟抽屜，焦點移到抽屜的標題。已經在「詳細資料」工作區，或中間是 ④、⑤ 時，照原本的方式切到「詳細資料」工作區。

## 流程步驟

| 步驟 | 左邊 | 中間 | 做什麼 |
|---|---|---|---|
| ① 輸入 | 資料中心蓋住整個主畫面 | | 載入收集檔或工作包、看覆蓋率、匯出 |
| ② 檢視 | 清單（設備、介面、IP、網段、MAC、VLAN） | 拓樸圖或 L4 可達性 | 看網路的結構，切換設備、L2 埠、L3 網段與 L4 可達性 |
| ③ 分診 | 檢查結果 | 拓樸圖或 L4 可達性 | 決定每個問題要修、接受或標為誤報（開啟頁面時的預設） |
| ④ 修正 | | 修正計畫 | 選取檢查結果，產生並下載 `.rsc` |
| ⑤ 驗證 | | 本輪變化、處理紀錄、修正追蹤、改善趨勢、比對 | 重新收集後確認哪些已修好、哪些回歸 |

- 每一步旁邊寫出目前的狀態：① 已收集的台數、② 拓樸圖的層級、③ 待處理的筆數（錯誤＋警告，不含提醒；基準狀態卡與 ⑤ 改善趨勢的「待處理」是同一個數字）、④ 已選的項目數、⑤ 處理紀錄是第幾輪（有回歸時另寫回歸數）。
- 按一步就切換，焦點移到這一步的標題。切換時拓樸圖的位置、縮放與選取都保留，不會重新排列。
- 還沒有基準時 ④、⑤ 不能用，按了會說明原因；清除基準時，停在 ④、⑤ 的畫面回到 ③。
- 在 ④、⑤ 點選檢查結果或比對的項目時，步驟不切換，詳情在右邊顯示。搜尋與路由追蹤會回到上一次看拓樸圖的 ② 或 ③。

## ① 輸入（資料中心）

按步驟列的「① 輸入」或頁首的「資料中心」開啟。這裡集中本輪所有的輸入與輸出，全部在本機處理。

- **開關**：開啟後焦點移到標題。再按一次「資料中心」、按「回到「③ 分診」」（名稱是你原本所在的一步）或按 Esc 關閉，焦點回到開啟它的按鈕。建立基準或原文的對話框開著時，Esc 先關對話框；焦點在頁首的搜尋或路由追蹤時，Esc 由它們處理。資料中心開著時，Tab 不會移到被蓋住的畫面。從搜尋、基準狀態卡等處選取設備或檢查結果時，資料中心自動關閉。
- **本輪的輸入**：每一列寫出項目、來源、狀態與操作。狀態一律有符號或文字（✓、!、✗、未載入），不只靠顏色。
  - 收集檔：來源名稱（由工作包帶回時註明；貼上的內容寫成「（貼上的內容）」）、已收集的台數與收集失敗的段數；「載入收集檔…」開啟建立基準的對話框。
  - 上一輪的基準：已載入的舊基準與比對摘要（新增、移除、變更），或由工作包帶回、等本輪的收集檔載入後比對；「載入舊基準（JSON）…」。
  - 處理紀錄：目前是第幾輪、共幾輪幾項，或停用的原因；「匯入處理紀錄…」。
  - 命名規則：名稱與版本、是否已套用；「變更…」開啟建立基準的對話框選擇。
  - 各類設備應收資料：幾類設備、是否使用（會改變基準鍵），目前只會由工作包帶回。滑過項目名稱可看說明（建立基準的選項 `expectedData`）。
  - 預期現況：檔名與比對結果；「載入預期現況（JSON）…」。格式是 `ssot-expected/1`（滑過項目名稱可看）。
  - 覆蓋率：已收集／應收集的網路設備台數，以及只被鄰居發現的網路設備（C01）；主機不在收集範圍，另寫台數。「看覆蓋率明細」捲到下方的覆蓋率；有 C01 時可「匯出 devices.csv 草稿」。
- **覆蓋率**：每台一列，缺少的資料與收集失敗以標籤列在同一列（已收集的資料寫在滑過時的提示）；有缺漏的排在前面，各欄可以排序。超過 600 台時只顯示前 600 筆，並註明共幾筆。
  - 「有缺漏」包括缺少應收集的資料與有指令收集失敗的設備。點收集失敗的標籤（指令與原因，滑過看影響的資料）開啟原始輸出的失敗行。
  - 篩選：全部已收集、有缺漏、未收集的網路設備、主機。主機是沒有收集、依鄰居（LLDP／CDP／MNDP）回報判斷為主機的設備，不在收集範圍。
  - 點一列在右邊看設備的詳細資料（資料中心會關閉）。基準狀態卡的「覆蓋率」連結也會開到這裡，只列有缺漏的設備。
- **本輪的輸出**：上方是工作包的內容與「匯出本輪工作包（ZIP）」，下方是五張卡片：
  - 給下一輪的自己：基準 JSON、處理紀錄 JSON。
  - 給設備：開啟修正計畫（④）；修正計畫有選取的項目時，註明會放進工作包。本工具只產生文字，不會連線設備。
  - 給報告或紀錄：檢查結果 Markdown、CSV（含處理狀態，不受 ③ 檢查結果的篩選影響）、「依設備排序」（工作包裡的報表也依這個設定）、拓樸 PNG。報表的內容見下方的「[儲存與匯出](#儲存與匯出)」。
  - 給收集器：devices.csv 草稿；有收集失敗時，列出只重收失敗指令的 `tools/collect.sh … --retry-failed` 指令。
  - 給之後的比對：由目前的基準產生預期現況。
- **下載工作包**：每個項目一個勾選框。收集檔與基準一定要放（勾選且不能取消）；基準用了命名規則或各類設備應收資料時，它們也一定要放。處理紀錄、預期現況、報表、修正 patch 可以取消；目前沒有的資料（例如處理紀錄停用、修正計畫沒有選取）不能勾選，並說明原因。收集檔可能含有設備機密，請自行保管。建立失敗時列出全部問題，不會下載。
- **載入工作包**：按「載入工作包…」選擇 ZIP。
  - 格式錯誤（例如檔案不完整、CRC 不符、收集檔順序不同）時列出全部問題與警告，目前的資料不變。
  - 載入成功時，先列出工作包的版本、建立時間、檔案數與警告，再勾選要帶回的內容：上一輪的基準（以工作包的收集檔重新建立並核對，取代目前的基準）、處理紀錄（整份取代）、預期現況（取代）；各類設備應收資料在重建時一定使用。
  - 命名規則選單預設是工作包附的，也可以換成目前清單中的，或不套用；和工作包不同時會提示：基準鍵會不同，處理紀錄會當成新的一輪。
  - 目前的處理紀錄有工作包沒有的內容（項目、內容不同或輪次）時，寫出會遺失什麼，提供「先匯出目前的處理紀錄」，要勾選「我了解，取代目前的處理紀錄」才會帶回。
  - 重建核對沒有通過時列出問題，什麼都不帶回。帶回後列出帶回的內容與警告。
  - 建立與讀取期間顯示忙碌提示並停用操作，大型資料可能要數秒，完成前畫面會暫停回應。帶回時重建基準的期間顯示重建進度，畫面不會停住。
- **接著做下一輪**：帶回上一輪的工作包後，再按「載入收集檔…」載入本輪的收集檔。建立基準時會自動以工作包的基準當成上一輪比對，並推進處理紀錄。
- **處理紀錄的匯出與匯入**：「處理紀錄 JSON」匯出；「匯入處理紀錄…」匯入。匯入會先檢查格式，不正確時列出全部錯誤、目前的處理紀錄不變；正確時確認後以匯入的內容**整份覆蓋**目前的處理紀錄（不合併），建議覆蓋前先匯出。處理紀錄也會放進工作包。資料格式與狀態規則見[設計說明 §10](設計說明.md#10-處理紀錄ssot-ledger1)。
- **建立基準的對話框**：可以貼上或選擇收集檔、載入範例資料、選擇命名規則。本輪有由工作包帶回的各類設備應收資料時，另有「使用工作包帶回的各類設備應收資料」的勾選框，預設勾選並註明類別數與「取消勾選會建立另一份基準」；取消勾選時這次建立不使用。還沒有基準時，歡迎畫面的「建立基準…」也開啟同一個對話框。
  - **格式說明**（預設收合）：收集檔的寫法與一段範例，「複製範例」把範例放進剪貼簿；瀏覽器不允許時會說明，請直接選取文字複製。
  - 已選的檔案各有一個移除鈕（✕），可以用鍵盤操作；移除後焦點移到下一個移除鈕或「選擇檔案…」。
  - **建立前的預檢**：貼上（停止輸入約 0.4 秒後）、選檔、載入範例或換命名規則時，立即寫出認到幾台設備、幾個指令區塊、幾段無法辨識，以及幾段有認不得的行。「查看清單」列出每台設備的區塊數與資料種類、每段無法辨識的位置與原因（建立後會列為 I01），以及有認不得的行的段落與行數（其餘內容照常建立；建立後會列為 I03），各最多 200 筆。原因和建立後的檢查結果是同一段文字。
  - 沒有認到任何設備時不能建立，預檢會說明每台設備要以「設備名 (管理 IP):」這一行開頭。預檢本身失敗（例如命名規則有誤）時不擋建立，建立時會回報同樣的錯誤。
  - 建立失敗或命名規則檔載入失敗時，原因寫在對話框下方的狀態列（「無法建立基準：…」「無法載入命名規則檔「…」：…」），不另跳出警告視窗。檔案不是有效的 JSON 時說明格式錯誤；非預期的程式錯誤請重新整理後再試，仍發生時回報括號內的原訊息。
- **歡迎畫面的收集指引**：「怎麼收集？指令清單與收集腳本」展開後，說明推薦的 `tools/collect.sh` 用法與手動收集的方式，列出每台設備要執行的指令（和收集器相同），可以「複製指令清單」；下方另列只有部分設備才需要的指令（Wi-Fi AP、CAPsMAN 控制器、VRF）。指令與格式見[收集清單](收集清單與輸入格式.md)。

## ② 檢視

左邊是清單，中間是拓樸圖。

### 清單

- 設備、介面、IP、網段、MAC、VLAN 六份完整清單，可以文字篩選；IP 已去重複。
- 清單種類、種類內的篩選（例如設備的全部／網路設備／主機／終端、IP 的來源、MAC 的缺 IP）與文字篩選在同一列；兩個下拉選單寫出各項的筆數，0 筆的項目不能選，選了之後焦點留在同一個下拉選單。可以排序的表頭是按鈕，用 Tab 移到後按 Enter 或空白鍵排序，排序後焦點留在同一欄。
- 表格寬於欄位時在自己的框內左右捲動，IP、MAC、VLAN 清單這類識別字不會被拆成兩行。
- 介面清單的狀態是 up、down、不明或停用（和介面詳情相同）；設備清單的廠商用正式的寫法（例如 MikroTik）。
- 網段是由設備自有介面位址推導的直連網段，列出設定的設備或介面，以及落在網段內的 IP 數。
- 基準有兩個以上的 VRF 時，IP 與網段清單每個 VRF 各一列，多一欄 VRF（同一個 IP 或網段在不同 VRF 是不同的位址）；點 IP 的列只看那個 VRF。只用 main 時沒有這一欄。
- 設備清單另有「終端」分類：一般的非 Wi-Fi 介面要恰好學到一個 MAC，而且沒有 LLDP／CDP 介面鄰接。
- Wi-Fi 介面本身不算終端介面，但每個 Wi-Fi MAC 的觀察位置仍列入終端清單，而且不參與 A02（MAC 可能因漫遊出現在多個 AP）。
- 同一個 MAC 的一般終端位置，只在 VLAN 相同或兩端都沒有記錄 VLAN 時比較；同一個 VLAN ID 分成多個不相連的 VLAN 片段時（例如各站點重用），只比較同一個片段內的位置。VLAN 片段是依鏈路證據的推論，所以 A02 是待核實的警告。
- 判斷終端時，只有 MNDP 廣播網域可達的不算直連鄰接。

### 拓樸圖

拓樸圖在 ② 和 ③ 都看得到。

- **工具列**：層級切換、VLAN 篩選、「全圖」、「版面 ▾」（重新排列；重新排列用的版面「分層（ELK）」或「快速（內建）」；力導向排列）與「顯示 ▾」（主機、終端、分群）。「顯示 ▾」的項目按了選單不關閉，可以連續切換；只對某些層級有用的項目在其他層級不出現。
- 版面預設為「分層（ELK）」：先以快速版面出圖，再於背景用 ELK 做多輪交叉最小化後替換。網路設備超過 1500 台或計算失敗時，維持快速版面並提示原因；可以在「版面 ▾」切換「快速（內建）」，選了就依新的版面重新排列。
- 同一層的設備太多時折成多列，讓整群接近畫面的比例，各列的台數平均：寬螢幕一層超過 6 台才可能折行，每列最多 24 台；直長的排列每列最多 6 台。快速與分層版面都一樣（分層版面依 ELK 排好的順序折行）。
- 窄螢幕上圖的區域高大於寬時，設備圖改成直長的排列（由上往下、同一層的設備較少、分群上下排），全圖時才不會又扁又小；只在排列時判斷，已排好的位置不會因為轉動畫面而改變。
- **分群**：每群的名稱標在群框的上方，和別的標籤重疊時改放在框內左上，兩處都放不下就不標。名稱太長時依序改用簡稱（括號前的部分）、簡稱的最後一段、截斷加「…」，畫面上兩群的標籤不會相同。滑過標籤或群框時顯示完整的名稱。只有一台設備的群不畫框，名稱仍標在原處，滑過標籤看全名。分群標籤與設備名稱不超出畫布的左右邊緣，也不放在工具列底下。分群是依鏈路自動分出的，不代表實體位置或 IP 網段；設備詳情的分群標籤也這樣說明。沒有命名規則、整張網路又連成一大片時，畫面會再依鏈路密度切成「分群 N（群內代表設備…）」排列，這只影響畫面。
- 設備名稱在畫面上固定 13px，縮小時不會變成小字（太擠時略過）；縮得很小時只留已收集的路由器與防火牆的名稱，窄螢幕全圖時仍看得到主幹，其他設備放大才出現。節點內的小字（廠商縮寫、數量）在畫面上小於 11px 時不畫。
- **全圖與聚焦**：顯示分群時，「全圖」連同群框與框上方的標籤一起放進畫面。「全圖」與聚焦會避開疊在圖上的工具列、圖例、操作提示、通知與窄螢幕的詳情抽屜（展開後太高的圖例不避開，可以先收合它）。節點很少時不會放得太大。選取一台設備時，連同它的一跳鄰居一起放進畫面，倍率最多 1.5 倍（看得到埠名）；選取路由追蹤時，去程與回程經過的設備都放進畫面。
- 只畫 L2 鄰接；同兩台設備之間有多條鏈路時合併成一條，畫成中間有細縫的雙線。
- 只有 MNDP 的設備對不畫線（MNDP 只證明同一 L2 廣播網域可達，不代表直連），但仍列在設備的鄰居表與鏈路詳情。OSPF 鄰接也不畫成拓樸的鏈路。
- 沒有 LLDP 的設備（例如 SwOS 的 CSS106、CSS610）依 MAC 表、點對點網段推定「推論鏈路」，以長虛線表示，點選可看依據與信心。接在這類交換器底下的終端，依上一跳的 MAC 表推定位置（埠不明），畫在該交換器下。
- 鏈路兩端的埠名在畫面上固定 12px（比設備名稱小），放大時顯示，和其他標籤重疊時略過；滑過鏈路或節點（以及選取鏈路）時不受縮放限制，彼此重疊時沿線往外挪開，挪不開才略過，也不蓋住設備名稱。
- 符合終端條件的位置，以終端節點畫在所屬設備下方（可以收合、可以關閉）；同一台設備的終端太多時收合成「終端 ×N」。Wi-Fi MAC 觀察位置也保留圖面提示，多個 MAC 以菱形呈現。
  - 點節點或「終端 ×N」：右邊顯示每個埠的 MAC、IP、廠商、VLAN；點一列跳到那個介面。設備頁也有同樣的清單。
  - 搜尋 MAC 或 IP 時，圖上會標出它所在的那個終端；點檢查結果 A03 會顯示該設備的終端清單。
  - 「顯示 ▾」的「終端」可以整個關閉。位置會和其他節點一起保存。
- **推定偏離**：點跨設備一致性檢查的檢查結果時，依多數決推定與其他設備不同的設備，在節點外另畫一圈紫色虛線（比選取的藍色環更外圈）。這是推論，不代表一定是那台設錯；沒有多數（平手）時不標。展開或收合終端時保留，選取別的東西時清除。
- 圖例（左下，預設收合）分「設備／終端／鏈路／鏈路註記／標示」五類，和圖上一致：
  - 嚴重度除了顏色還有外形：錯誤是方形、警告是三角形，標在設備右上角（主機與終端也有）與有問題的鏈路中點。
  - 鏈路依速率分色，線寬隨速率遞增（1G → 10G → 40G，聚合最粗）；1G 是依介面名稱推估的分類，不代表實際協商速率。
  - 「只有一端資料」（對端沒有鄰居資料，只有本機這一端回報）是點線、推論鏈路是長虛線，顏色仍依鏈路類別。只有一端資料不是「LLDP 單向」（對端有鄰居資料但沒回報這條鏈路，K01）。連到 Wi-Fi 與容器 veth 介面終端的鏈路各有專用線型。
  - 終端依廠商上色，只取終端數量最多的前 8 個廠商，其餘與不明廠商歸「其他」的中性色。
  - 「標示」列出嚴重度的外形，以及選取（藍色粗環）、滑過（深色細環，鍵盤 N 移到的設備也是）、搜尋結果、推定偏離（紫色虛線外圈，推論）與路由追蹤（含箭頭）的樣式。
  - L2、L3 另有：埠（L2）、網段（L3）、路由（L3）、網段重疊（L3），以及 VLAN 篩選的四種線型。
- 鍵盤：點一下拓樸圖（或用 Tab 移到它）取得焦點後可以操作；移到的設備會讀給螢幕閱讀器。L2 埠圖與 L3 網段圖也一樣，N／Shift+N 輪流移到節點。

  | 按鍵 | 動作 |
  |---|---|
  | N／Shift+N | 依畫面位置（由上而下、由左而右）移到下一台／上一台設備，移出畫面時自動平移 |
  | Enter／空白鍵 | 選取 N 移到的設備並開啟詳情 |
  | Shift+Enter | 聚焦到 N 移到的設備（同雙擊） |
  | Esc | 取消選取 |
  | 方向鍵 | 平移（按住 Shift 移動較多） |
  | +／- | 以畫面中央為中心放大／縮小 |
  | 0 | 全圖 |

- 觸控：拖曳空白處平移、拖曳節點移動位置；兩指開合縮放（以兩指中點為中心，同時可以平移），放開一指後剩下的手指接著平移。點一下選取，在同一個節點附近快速點兩下等同雙擊（聚焦，或展開「終端 ×N」）。觸控的點擊半徑在畫面上至少 22px，小的終端節點也點得到。
- 系統設定為減少動態效果時，不播轉場動畫，「力導向排列」直接顯示結果。

### 層級：設備、L2 埠、L3 網段、L4 可達性

- **切換**：工具列的「設備」「L2 埠」「L3 網段」「L4 可達性」四種。這是一組選項按鈕：Tab 移到選取的那一個，←、→（或 ↑、↓）、Home、End 切換。② 的步驟狀態寫出目前的層級。L4 不是圖，操作見下方「[L4 可達性](#l4-可達性)」。
- 切換時選取保留，在新的一層重新標示；各層的平移與縮放分開保存。「重新排列」只重排目前的層級。「終端」「分群」只在設備圖顯示。
- **L2 埠圖**：設備是方框，埠是框邊上的小方塊（聚合埠較寬，推論鏈路未收集端的未知埠是虛線），線接在埠上；只畫 LLDP／CDP 介面鄰接與推論鏈路。
  - 選項：「展開聚合」（成員各自畫成一個埠；預設收合）、「全部的埠」（也畫沒有接線的實體、聚合與無線介面）、範圍（「整張圖」或「選取的設備與鄰居」）。
  - **焦點模式**：範圍是「選取的設備與鄰居」時，只畫一台設備與它的鄰居。雙擊鄰居的設備框（或 N 移到它後按 Shift+Enter）改以它為中心；選取不在圖上的設備時，也會改看那一台。設備超過 300 台時只能用焦點模式，「整張圖」不能選，圖的上方說明原因；沒有選取設備時，先看鏈路最多的路由器、防火牆或交換器。
  - 點設備框開啟設備詳情；點埠開啟介面詳情（未知埠開啟設備詳情）；點埠之間的線時，只有一條鏈路開啟鏈路詳情，多條時開啟這對設備的鏈路清單。
- **L3 網段圖**：網段是圓角長條，設備是節點，位址把設備接到網段；鄰居回報的位址與管理 IP 是推論，用較淡的線型。接到兩個以上網段、有路由表或是路由器／防火牆的設備是路由設備（推論）。
  - 「顯示路由」：以虛線箭頭畫出靜態路由與預設路由，從路由所在的設備指到目的網段；只由路由得知的網段用虛線外框。
  - 互相包含的網段之間畫警告色的虛線，中點有警告外形；網段下方另標「重疊網段」「重複 IP」。
  - **VRF**：基準有兩個以上的 VRF 時，每個 VRF（含 main）畫成一個框，取代原本的分群。同一個網段在不同 VRF 各自獨立；一台設備在每個有位址的 VRF 各一個節點，main 以外的標上 `@VRF`（例如 `TPE_PE_RT_01@cust-a`）。圖上方的說明寫出有哪些 VRF；「顯示路由」時，只用於策略路由的路由表（不屬於任何 VRF）的路由不畫，說明寫出省略了幾條，這些路由列在設備詳情的路由表。只用 main 時畫面和加入 VRF 之前相同，沒有 VRF 框。
  - 點網段、重疊線或路由開啟網段詳細資料；點設備開啟設備詳情（`@VRF` 的節點也開啟同一台設備）；點位址的線開啟那個介面。選取設備時，這台設備在每個 VRF 的節點都會標示；選取介面時只標它所屬 VRF 的節點。
  - **網段詳細資料**：網段、VLAN、路由設備、閘道（DHCP 網路）、VRF（同一個網段也在其他 VRF 時，列出那些網段的連結，它們是不同的位址空間）；位址（IP、設備或介面、依據與是否推論、來源行，重複的 IP 另外標示）；接在這裡的設備；重疊網段（包含或被包含）；重複 IP；路由到這個網段的路由（設備、協定、路由表（有多個 VRF 時）、下一跳、經由的網段）；以及相關的檢查結果。
- 「匯出 PNG」（頁首的「⋯」，資料中心也有）畫的是目前的層級，有畫布底色、不是透明背景；檔名是 `topology.png`、`topology-l2.png` 或 `topology-l3.png`。L4 可達性沒有 PNG，在 L4 按「匯出 PNG」時以通知說明，改用 L4 畫面的「下載 CSV」。

### VLAN 篩選

工具列的「VLAN：不篩選」選單，或在詳情選一個 VLAN。在設備圖與 L2 埠圖標出承載這個 VLAN 的鏈路，L3 標出這個 VLAN 的網段。

| 線型 | 意思 |
|---|---|
| 實線 | 承載：兩端都帶這個 VLAN |
| 長虛線 | 推論承載：推論鏈路，已收集的各端都帶 |
| 錯誤色實線加垂直短刻度，中點有錯誤外形（方形） | 只有一端帶：兩端都有 VLAN 資料，只有一端帶（V01） |
| 淡色點線 | 一端未知：只有一端可確認（對端沒有收集、沒有 VLAN 資料、只有一端資料，或在沒開 vlan-filtering 的 bridge 上），推論 |

- 滑過鏈路時，提示寫出承載狀態與原因；VLAN 詳情另列「只有一端可確認的鏈路（推論）」與原因。
- 篩選會一直保留，直到在選單選「不篩選」；選設備、鏈路等其他東西時，沒有自己的標示的地方仍標出這個 VLAN。（2.10.0 以前，選了別的東西篩選就會消失。）
- 同一個 VLAN ID 分成幾個不相連的 VLAN 片段時（例如各站點重用），詳情會列出各片段，可以只看其中一個，按「顯示所有 VLAN 片段」回到全部。VLAN 片段是依鏈路證據的推論。

### L4 可達性

在工具列選「L4 可達性」（② 和 ③ 都可以）。中間換成 zone 矩陣與可達性查詢，拓樸圖暫時收起，回到其他層級時照原樣還原。這裡的結果全部是依基準的路由與防火牆規則**推論**出來的，不寫進基準，判斷規則見[設計說明 §5.3「L4 可達性與 zone」](設計說明.md#l4-可達性與-zone2110-新增)。

- **判斷的前提**（最上方，標「推論」）：只判斷新連線（回程由連線追蹤放行）、只套用 raw、nat、filter（不含 mangle、bridge filter 與主機本身的防火牆）、只算 IPv4、封包在入介面所屬的 VRF 查路由、策略路由無法判斷時結果為不明、address-list 的內容一律無法判斷等。看結果前先讀這幾條。
- **zone 矩陣**：列是來源 zone，欄是目的 zone。
  - 每一格寫出狀態的符號與文字，不只靠顏色：✓ 允許、✕ 拒絕、◐ 部分允許、? 無法判斷、– 沒有組合（斜線底紋）。數字是「允許／總數」：每個 zone 取代表位址，代表位址 × 目的 × 服務各算一次。
  - 「≠ 結果不一」表示同一個 zone 的成員結果不一致：zone 可能分得不對，或規則只放行部分位址。對角線（來源與目的是同一個 zone）是虛線外框，zone 內的流量主要受主機防火牆影響，不在範圍內。
  - 圖例在矩陣上方；狀態列寫出 zone 數、代表位址數、dst-nat 入口數與判斷次數。
  - **服務**：選單可以選「全部服務」或單一服務（例如 `tcp/443`）；選項是預設的服務，加上 dst-nat 規則的目的埠。
  - **VRF 篩選**：zone 分在兩個以上的 VRF 時，服務選單旁有「VRF」選單（「全部 VRF」或「來源在 VRF x」）。只篩來源 zone（列），目的 zone（欄）全部保留，所以跨 VRF 的格子（路由洩漏）照樣看得到；矩陣上方寫出篩選後的來源 zone 數。表格檢視與 CSV 也只列篩選後的格子。
  - **矩陣／表格**：表格檢視每一格一列，可以排序，點一列往下看。zone 超過 60 個時只能用表格；表格最多列 3000 格，完整內容用「下載 CSV」。zone 在多個 VRF 時，表格最後多「來源 VRF」「目的 VRF」兩欄。
  - **下載 CSV**：目前服務的矩陣，每一格一列（欄位見[設計說明 §11.5](設計說明.md#115-匯出)）；zone 在多個 VRF 時最後多「來源 VRF」「目的 VRF」兩欄，有 VRF 篩選時檔名加上 `-vrf-<VRF>`。
  - 第一次開矩陣時，大型網路要數秒，期間顯示「計算 zone 矩陣中…」與分段進度（第 1／3 段找代表位址、第 2／3 段逐一判斷、第 3／3 段整理格子，各寫出已完成的筆數）。計算期間仍可操作，例如切換層級、捲動或改看表格；換服務或離開 L4 時停止計算，狀態列寫出已停止，回到 L4 時重新計算。同一份基準再開，或切回算過的服務時，直接顯示結果，不再計算。
- **滑過格子**（或用鍵盤移到格子）時，提示寫出允許、拒絕、無法判斷的筆數、是否結果不一、代表規則與無法判斷的原因。
- **鍵盤**：L4 畫面在工具列之後，Tab 先經過工具列再進入畫面。矩陣只有一個 Tab 停點（目前的格子），用方向鍵移動，Home／End 到這一列的頭尾，Ctrl+Home／Ctrl+End 到整個矩陣的頭尾；Enter 或空白鍵往下看，Esc 收起提示。開啟明細時焦點移到明細的標題，按「關閉明細」後回到原來的格子。
- **明細**（點格子或按 Enter）：上方寫出這一格的狀態、筆數與目前的服務，以及無法判斷的原因（滑過原因可看代碼的說明）。
  - **位址組**：每一列是一個目的與一組結果相同的來源代表，寫出各服務的結果、狀態與閘道或入口。目的是 dst-nat 的入口時標出改寫後的位址。來源有多個時寫「… 等 N 個」，滑過看每個位址與它是 ARP 看到的還是推算的。
    - 結果一致的格子同時有拒絕和其他結果時，全部拒絕的組預設收起，可以按「顯示全部拒絕的組」展開。
    - **結果不一的格子**：預設只列出造成差異的組，上方說明共有幾組、列出幾組，按「顯示全部（N 組）」看全部，再按「只顯示造成差異的組」收回。造成差異是指某個服務的結果和同一個目的的其他來源、或同一批來源往其他目的的結果不同，而且是少數（平手時兩邊都算）；那個服務的結果標「≠ 差異」，另有「造成差異的服務」一欄。
    - 點一列看第一個服務的逐跳路徑，點某個服務的結果看那個服務的。
  - **牽涉的規則**：決定結果的規則、chain 結尾的預設與路由，以及條件無法判斷的規則，各有允許、拒絕、無法判斷的筆數與服務。點規則在右邊開啟規則詳情（命中次數與 L4 影響，見[右側的詳細資料](#右側的詳細資料)的「防火牆」）。
  - **逐跳路徑**：
    - 最上面是結論（允許、拒絕、無法判斷），有 NAT 時另寫 NAT 之後的目的。
    - 「起點」說明封包從哪裡進入：來源網段的閘道（依 DHCP 網路、網段上有路由表的設備或已收集的設備）、網路設備自己送出，或來源與目的在同一個網段。
    - 「決定結果」列出決定結果的規則或路由（例如沒有符合的路由、黑洞路由）。無法判斷時列出原因（例如規則的條件無法判斷、設備沒有收集），其他結果的同類說明列在「附註」。
    - 每條路徑逐跳列出：設備與 chain、這一跳的結果、位址（被 NAT 改寫時寫出改寫後的位址）、入與出的介面、使用的路由，以及各關（`raw prerouting`、`nat dstnat`、`filter forward` 等）由哪條規則決定、NAT 前後的位址、設備的服務是否接受。有 ECMP 或多個閘道時，每條路徑各列一次。最後一行是路徑的結束原因。
    - 有多個 VRF 時，設備旁標出這一跳的 `@VRF`，結束原因旁寫出 VRF；使用的路由另寫出查的路由表（不是 VRF 的表時）、經過的 VRF 介面與決定查表的 `/routing rule`，閘道在別的 VRF 解析時寫成 `位址@VRF`。結束原因是策略路由不明或被 `/routing rule` 丟棄時，列出相關的規則。
    - 「這次查詢的前提」預設收合。
- **可達性查詢**：輸入來源 IP、目的 IP、協定（tcp、udp、icmp）與目的埠，按「查詢」或在欄位中按 Enter。icmp 不用填埠（欄位停用）；tcp、udp 一定要填。結果以同樣的逐跳路徑顯示在矩陣下方，不屬於任何格子；位址不是有效的 IPv4 或參數不對時，寫出原因。
  - **VRF**：基準有兩個以上的 VRF 時，表單多一個「VRF」選單，預設「依來源位址決定」。來源位址在多個 VRF（位址重疊）時不猜，逐跳路徑寫出有哪些 VRF，並列出「用 VRF x 查詢」的按鈕，按一個就用那個 VRF 重新查詢。有多個 VRF 時，逐跳路徑的標題寫出這次查詢的 VRF。從位址組點進來時，用那個代表位址的 VRF 查詢。
- **zone 的依據**（最下方，標「推論」）：每個 zone 的名稱、來源（命名規則、interface list、VLAN、網段）、依據、網段與設備數；名稱旁的「推論」標示這個 zone 是推論來的。展開「每個網段的依據」可以看每個網段用了哪個來源，以及其他來源會得到的 zone，用來檢查分得合不合理。
  - 每個 VRF 的 zone 分開計算，main 以外的 zone 名稱標出 VRF；zone 在兩個以上的 VRF 時，兩張表都多一欄 VRF。
  - 命名規則有 `zones` 段時，以命名規則的標籤為準（不是推論）。命名規則和建立基準時用的不是同一份（例如改了 `zones` 卻沒改 version，或基準是 2.11.0 以前建立的）時，不套用 `zones` 段，在狀態列與這裡寫出原因；要用同一份命名規則重新建立基準（[命名規則「zones」](命名規則.md#zones選用2110-新增)）。
- 搜尋與路由追蹤是「在圖上定位」，在 L4 時會改回設備圖。

<a id="step-triage"></a>

## ③ 分診

左邊是檢查結果，中間是拓樸圖，右邊是證據與處理建議。開啟頁面時預設在這一步。

- 點任一筆，圖上會定位並標紅。沒有發現的規則列在下方，分成「通過」與「沒有資料可檢查」（預設收合）；這些規則也可以展開「常見原因與處理」，看處理建議。
- 每筆旁邊的「處理」可以變更它在處理紀錄中的狀態：待處理、已排定修正、可接受（豁免）、誤報、已修好，並可填備註。
  - 選單只列目前狀態可以改成的狀態。
  - 選「可接受」要填原因與到期日（預設約半年後）；到期後，下一次建立基準時自動改回待處理。
  - 「已修好」只能用在這一筆已不在目前基準時；平常是重新收集、建立基準後自動判定。修好後又出現的標為「回歸」。
  - 不合法的變更會在欄位下方說明原因。
- 已處理（已排定修正、可接受、誤報、已修好）的項目依狀態各列一組（預設收合），顯示狀態、時間、豁免原因與備註，不計入上方、步驟列與基準狀態卡的筆數（狀態卡會註明另有幾項已處理）。有標為誤報的規則時，另列「誤報率最高的規則」。
- 處理紀錄只存在這個瀏覽器，不改變基準；清除基準不會清掉它，之後重新建立同一份網路的基準時仍然有效。舊版的「確認」紀錄在第一次建立或還原基準時自動轉換成處理紀錄（未分類的視為可接受），提示列會顯示轉換的筆數。
- 可以切換「依規則」或「依設備」分組。
  - **依規則**：分成三層，類別（輸入、覆蓋、鏈路等，和[基準檢查規則](基準檢查規則.md)的章節相同）→ 規則 → 結果，順序和規則目錄相同。類別標題寫出這一類待處理的錯誤、警告、提醒各幾筆（文字加外形）；有錯誤或警告的類別預設展開，只有提醒的預設收合，自己展開或收合後會保留到換基準為止。展開一條規則時，結果上方先列一句「處理：…」，就是[基準檢查規則](基準檢查規則.md)該規則「處理」的第一句。
  - **依設備**：不屬於任何設備的檢查結果（例如沒有設備標頭的 I01）排在最後一組。
- 跨設備一致性的檢查結果，在結果下方列出「推定偏離（多數決）：」的設備（推論），點設備名選取那台設備；沒有多數（平手）時沒有可指出的設備，清單與詳情都不顯示這一行。
- **只看新出現的**：在 ⑤ 驗證的比對或資料中心載入舊基準後才出現，可以只列出舊基準沒有的檢查結果；沒有按下時，新出現的那幾筆標「新出現」。兩份基準的程式版本不同時，旁邊提示新出現的可能只是新版才有的檢查。沒有載入舊基準（或比對失敗）時不顯示這個選項；建立或載入新的基準後，要重新載入舊基準。
- **從其他地方選取檢查結果**（基準狀態卡、詳細資料、防火牆畫面、⑤ 的本輪變化等）：③ 的清單展開到這一筆所在的類別與規則（依設備時是那台設備；已處理的是它的狀態分組），必要時打開被篩掉的嚴重度、取消「只看新出現的」、多顯示幾筆，再標出這一筆並捲到看得到的地方。
- 中間的工具列也可以切到「[L4 可達性](#l4-可達性)」，看防火牆的檢查結果實際影響哪些 zone 之間的連線。點防火牆規則的檢查結果時，右邊的規則詳情另有命中次數與「計算 L4 影響」（見[右側的詳細資料](#右側的詳細資料)的「防火牆」）。
- 「匯出報表…」開啟資料中心的報表；「修正計畫…」到 ④ 修正。

<a id="step-fix"></a>

## ④ 修正

中間是修正計畫，佔滿全寬。從步驟列的 ④、③ 的「修正計畫…」，或防火牆畫面的「在修正計畫中開啟」進來。**本工具只產生文字，不會連線或改動任何設備**；套用前請逐行審查，自行以 `/import` 執行，之後重新收集、建立基準確認結果。

- **要修正哪些**：
  - 依規則：寫成「類別 ▸ 規則標題」。每個類別是一個預設收合的框，標題寫出有幾條規則與已選幾項；展開後列出規則標題（可產生指令的排前面），點一下選取或取消這條規則的全部，滑過看規則代碼。
  - 依設備：「加入這台的全部」；或「全部清除」。
  - 逐筆勾選：收在「逐筆勾選（N 條規則）」（預設收合，有展開的規則時展開），展開規則逐筆勾選。同一條規則、同一組設備有多個檢查項目時（例如 A12 的 DNS 與 NTP），各自一列，可以分別勾選。
  - 換了基準時選取會清空。
- **計畫**：依設備列出每一項的規則標題、修改前（基準的原文，可以開啟原始輸出）與修改後（套用指令）、說明與風險。每台設備可以切換檢視套用、回復、驗證三個 `.rsc`，複製或下載目前檢視的那一份。上方的「下載全部（N 個檔案）」下載每台設備的三個 `.rsc` 與一份總表（Markdown）；「其他格式 ▾」可以只下載總表。沒有產生指令的項目依原因分組列出。要一個檔案帶走時，可以在資料中心匯出工作包（含這裡選取的 patch 與總表）。
- 目前 F01、F02、F06 能產生停用規則的指令，A12（DNS／NTP 伺服器）可以在「需要選擇的項目」選擇要採用的值；其他檢查結果，以及 `find` 無法只找到一條規則的情況，列出沒有產生指令的原因。
- **需要選擇的項目**（A12）：每筆列出選項：改成多數設備的值、改成某一組設備的值，或「不修改」。
  - 多數的選項標示「推論」，並寫出「N 台中 M 台」；預設採用它，可以改選。
  - 沒有多數時，要先選擇才會產生指令。
  - 選了某一組後，其他組的設備會產生指令；每一項顯示修改前 → 修改後（例如「10.1.10.2 → time.cloudflare.com」）與警告，並標示「依選擇」。
  - 選「不修改」時，填原因與到期日，按「標為可接受」寫進處理紀錄。
  - 選項是一組選項按鈕，可以用鍵盤切換；切換後焦點留在剛選的選項。
  - 下載的總表多一段「需要選擇的項目」，列出每筆目前的選擇，以及是預設（多數決，推論）還是使用者選擇。
- 畫面夠寬時（約 880px 以上），左邊是「要修正哪些」（捲動時固定），右邊是計畫；較窄時上下排。修正的規則與 `.rsc` 的寫法見[設計說明 §9](設計說明.md#9-修正-patchssot-patch1)。

<a id="step-verify"></a>

## ⑤ 驗證

中間佔滿全寬，重新收集、建立基準後，在這裡確認哪些已修好、哪些回歸。畫面夠寬時，左欄是本輪變化與處理紀錄（捲動時固定），右欄是修正追蹤、改善趨勢與比對。

- **本輪變化**：新出現、已修好、回歸（修好後又出現）、豁免到期，以及因收集失敗而無法判斷的項目（所屬設備有收集失敗或沒有收集時，消失的問題不判定為已修好）。目前基準有這一筆時，點一下定位。和上一輪的基準版本不同時，提示新出現的可能來自新版檢查。同一份基準已經推進過（例如重新開啟頁面）時，說明沒有新的變化。
- **處理紀錄**：各狀態的筆數與處理紀錄的說明收在「各狀態的筆數與說明」（預設收合）。豁免沒寫原因時提醒補上。「在資料中心匯出或匯入…」開啟資料中心的處理紀錄。
- **修正追蹤**：已排定修正的項目（標示目前基準仍有或沒有），以及累計已修好的項目；上方列出已排定修正、目前基準仍有、累計已修好三個數字。
- **改善趨勢**：每建立一份新的基準算一輪。
  - 上方的數字卡：待處理（目前基準的錯誤＋警告，下方寫出各幾筆；和步驟列 ③、基準狀態卡同一個數字）、提醒（不算進待處理）、已豁免、覆蓋率與終端埠。只有一輪時只列這些數字。
  - 兩輪以上畫出每一輪的「未結案（含提醒）」、回歸、已豁免的筆數，以及覆蓋率與終端埠數的變化。「未結案（含提醒）」是處理紀錄每一輪仍待處理的筆數，不分嚴重度，所以和上方只算錯誤與警告的「待處理」不同。
  - 三條線以圓形、方形、三角形區分，圖例與提示也畫出同樣的外形；線尾寫出名稱與數值。
  - 滑過圖，或用 Tab 移到圖上（每張圖停一次）再以 ←、→、Home、End 切換輪次，可以看每一輪的數值與建立時間。
  - 「表格檢視」列出同樣的數字。
- **比對**：
  - **預期現況比對**：按「載入預期現況（JSON）…」載入確認過的應有現況（格式 `ssot-expected/1`，範例見 [`samples/expected-sample.json`](../samples/expected-sample.json)），和目前的基準比對；也可以在資料中心載入。預期現況是本輪的輸入：建立或載入新的基準後保留，自動和新的基準重新比對。由目前的基準產生預期現況的按鈕在資料中心的「本輪的輸出」。
  - **與舊基準比對**：載入之前用資料中心的「基準 JSON」存下的基準，依設備、鏈路、VLAN、IP、防火牆、檢查結果分組列出新增、移除與變更；防火牆規則讓 WAN 多出可連入點的標示為「新暴露」，可以單獨篩選。兩份基準的程式版本或命名規則不同時，比對結果上方會提醒：新版才有的檢查會顯示為新出現，名稱與分群可能因命名規則而不同，這些差異不代表網路改變。
  - 點一列在右邊開啟那個項目。比對結果不會儲存，兩種比對都只讀取基準，不會修改它。

## 右側的詳細資料

- 鄰居（含類別與 LLDP／MNDP／CDP 協定）、OSPF L3 鄰接、介面（埠模式、PVID、untagged／tagged VLAN、所屬聚合／bridge）、VLAN、MAC、路由表。
- 介面的狀態照 RouterOS 寫 up、down，停用的介面寫「停用」。
- 設備詳情的「廠商」用正式的寫法（例如 MikroTik）；「鄰居回報的功能」（LLDP、CDP 回報）寫成中文，例如「橋接、路由」，滑過看原值，認不得的項目照原值顯示。「看到它的設備」超過 5 台時，從屬性表移到下方預設收合的區塊。
- VLAN 詳情的線型說明與終端畫面的判斷說明收在預設收合的「這是什麼？」；沒有任何設備替 VLAN 取名時不列名稱。
- 鏈路的證據寫成「雙向確認」、「只有一端資料（對端沒有鄰居資料）」或「LLDP 單向（對端沒回報）」（K01）；只有 MNDP 的寫「同一 L2 廣播網域可達（MNDP，未確認直連）」。
- **MAC 詳情**分三段：
  - 事實：ARP 的 IP，以及 Wi-Fi 關聯表與 DHCP 的 SSID、頻段、主機名稱、位址與訊號。
  - 位置（推論，標「推論」）：終端埠、Wi-Fi 位置，或推定在未收集的交換器底下；推定不出來時寫「無法推定（沒有學到它的終端埠）」。
  - 學到它的介面：先列位置所在的介面（終端埠、Wi-Fi 介面、推定位置的上一跳）；其餘是轉送路徑上的埠，收合成「另在 N 個非終端埠學到」。每列的 VLAN 都相同時，VLAN 寫在這一段的標題旁，不另列一欄；都是動態學到時不列類型欄。
- 介面詳情列出 bridge 的 vlan-filtering（開或關；關時標示「VLAN 原樣轉送，不看也不改標籤」）。介面在沒開 vlan-filtering 的 bridge 上時，PVID、frame-types、ingress-filtering 旁邊標示「沒有作用（bridge 沒開 vlan-filtering）」（推論，依 RouterOS 手冊）。
- **VRF 與策略路由**（只用 main、也沒有策略路由的網路不顯示這些欄位與區塊，畫面和加入 VRF 之前相同）：
  - 介面詳情的「VRF」寫出介面所屬的 VRF 與判斷依據（設備回報的 `vrf=`、`/ip vrf print` 的順序、export 的 `/ip vrf`，或沒有列在任何 VRF 而屬於 main）；依 export 判斷的標「推論」（export 不寫內建的 main，假設 main 排在最後）。
  - 設備詳情的「VRF」區塊：依設定順序列出這台設備的 VRF（內建、停用）、設定的介面、歸到這個 VRF 的成員與來源行。只有內建的 main 時不顯示；來源是 export 時標「推論」並說明原因。
  - 設備詳情的「策略路由」區塊（這台設備有 `/routing rule`、只用於策略路由的路由表、mark-routing 或改過的 policy-rules 時才顯示，和 VRF 無關）：`/routing settings` 的查表順序（policy-rules，改過預設的順序時標出查哪一張表無法判斷）、mangle 的 mark-routing 條數（mangle 不在模型中，結果不明）、這台設備的路由表（用途是哪個 VRF 或只用於策略路由、fib、狀態、路由數、來源行），以及 `/routing rule`（依設定順序，含停用的規則與來源行）。這裡只列設定；封包實際查哪一張表由路由追蹤與可達性判斷。
  - 路由表在基準有其他 VRF、或這台設備有 main 以外的路由表時，多一欄「路由表」；只用於策略路由的表另標「只用於策略路由」。下一跳的閘道在路由所在的 VRF 以外解析（路由洩漏、VRF 介面）時寫成 `位址@VRF`，滑過看在哪個 VRF 解析與依據。
- 設備的「收集到的原始輸出」列出每個指令的收集時間（UTC，收集器記錄的）與收集失敗；有失敗時預設展開。已解析的區塊中有認不得的行（I03）時，解析器欄另標「部分無法辨識（N 行）」，點一下開啟第一行。
- **基準狀態卡**：沒有選取任何東西時，右邊是這份基準的狀態，每個數字只出現一次。
  - 狀態句：待處理的錯誤、警告各幾項（不含已處理的，另註已處理幾項），點數字到 ③ 分診並只列錯誤與警告；「建議先看」連到最嚴重、規則順序最前的一筆（沒有對應的物件時直接開啟原文）。沒有時寫「目前規則未發現待處理的錯誤或警告」。
  - 依處理紀錄有回歸、因收集失敗而無法判斷，或豁免到期的項目時，另有對應的提示，點一下到 ⑤ 驗證的本輪變化。
  - 覆蓋率：有缺資料或收集失敗的網路設備台數，點一下開啟資料中心的覆蓋率並只列有缺漏的設備；都齊全時寫「已收集的網路設備資料齊全」。主機（沒有收集、依鄰居回報判斷為主機的設備）不在收集範圍，另寫台數。
  - 四個數字卡：已收集／應收集的網路設備、鏈路、VLAN（相異 ID）、MAC。下方一行是建立時間、命名規則與來源。
  - 「技術細節」（預設收合）：輸入指紋、基準鍵（處理紀錄以它判斷是不是同一輪）、版本、介面、IP（ARP）、路由、終端 MAC 位置、VLAN 定義筆數、不相連的 VLAN 片段數（推論）與解析器使用量。
  - 這些是該份 Snapshot 的檢查結果與覆蓋率，**不代表即時網路健康狀態**。每項規則的判斷條件與處理建議見[基準檢查規則](基準檢查規則.md)。
- **詳情的排列**：標題 → 標籤 → 檢查結果 → 屬性 → 其他區塊 → 來源。檢查結果放在屬性之前，依嚴重度排序，先列 5 筆，其餘收在「再顯示 N 筆」。超過 8 列的表格（介面、鏈路、MAC、終端埠、來源等）預設收合，展開列寫出筆數。
- **推論的標示**：和收集到的事實並列的推定值旁加「推論」標籤，滑過看依據，例如設備的類型依據（依命名規則指定的除外）。推定的介面類型寫在同一個標籤裡，例如「實體埠（推論）」，滑過看依據。
- 每筆檢查結果的「處理：…」是一句處理提示，就是[基準檢查規則](基準檢查規則.md)該規則「處理」的第一句；完整的處理建議在下方的「常見原因與處理」。
- **防火牆**：設備詳情的「防火牆」摘要規則數、有問題的規則數與 WAN 判斷狀態（「已找到 WAN 介面（推論）」「沒有 WAN interface list（推論）」或「WAN interface list 沒有成員（推論）」）；點「查看防火牆規則與服務」進入防火牆畫面，依位址族、表、chain 列出規則與相關的檢查結果，另列 WAN／LAN 判斷（推論）、`/ip service` 與 interface list。點選 F01–F07 的檢查結果時，會直接開啟防火牆畫面並定位到那條規則或服務。
- **命中次數**：防火牆畫面的規則表有「命中」欄（封包數，加千分位；滑過看位元組數）。定位到一條規則時，另列「命中次數」：封包、位元組與來源行。
  - 命中次數是收集當下的累積值，設備重開或 reset-counters 後從 0 重新計算。**0 只代表到收集時為止沒有比對到**，不代表規則沒用：備援、少見的流量或剛加上的規則都可能是 0。
  - 沒有數字時寫出原因：沒有收集這個表的 `print stats`、有 `print stats` 但這台沒有 export，或命中次數對不上 export 的規則。對不上時整個表都不採用，寫出第一個不符的地方（例如列數不同、某一列的 chain 或動作不同），旁邊的 F09 可以點開（[F09](基準檢查規則.md#f09)）。
- **L4 影響（推論）**：定位到一條規則時，按「計算 L4 影響」才計算（第一次要先算 zone 矩陣，大型網路約需數秒）。結果列出這條規則牽涉的 zone 對（決定結果、條件無法判斷、只是經過的筆數與服務）、是否被遮蔽（F01）或重複（F02），以及**停用這條規則後**結果改變的筆數（例如 allow→deny）與路徑。算過的結果保留到換基準為止。命名規則有 `zones` 段時，用和 L4 畫面相同的 zone。
- **修正（停用規則）**：防火牆畫面的「修正（停用規則）」列出這台設備（或定位到的那條規則）可以修正的檢查結果。F01、F02、F06 產生停用指令，附 find 的依據與風險，可以按「複製」；F03 要選擇處理方式，以及 `find` 無法只找到一條規則（例如 F02 的兩條規則完全相同）時，列出沒有產生指令的原因。指令以 comment 或規則的比對條件 `find`，不用規則編號。「在修正計畫中開啟」可以取得含前置檢查、回復與驗證的完整 `.rsc`。這只是文字，本工具不會連線或寫回設備。
- 跨設備一致性的檢查結果，詳情會列出「推定偏離（多數決）：」的設備（推論），點設備名選取那台設備；沒有多數（平手）時不顯示這一行。被推定偏離的設備，設備詳情的標籤列有「推定偏離 N 項」，點一下捲到檢查結果，這些檢查結果即使實體不是這台設備也列在這裡。
- 同一條規則、同一組設備可能有多筆檢查結果時，詳情會在標題旁標示「檢查項目」，例如 A12 的「DNS 伺服器」與「NTP 伺服器」。
- 詳情裡的每筆檢查結果都有預設收合的「常見原因與處理」，內容和[基準檢查規則](基準檢查規則.md)各章的「常見原因」「處理」一致；RouterOS 指令與欄位以等寬字型顯示。
- 點 A03（未知對端）會開啟該設備的終端 MAC 位置畫面，終端埠清單前面列出這台設備的 A03 與它的常見原因與處理。
- 每筆都能開啟原文並標示行號；VLAN、鄰居、OSPF、路由與原始輸出可以按需要展開。來源列寫成「設備 › 指令・第 N 行」。
- 檢查結果的證據合成一行「原文：第 N、M 行」，每個行號都可以點，最多列 3 處；超過時註明共幾處，其餘在原文對話框以「上一處」「下一處」切換。
- VLAN 詳情的「兩端都有此 VLAN 的鏈路 N 條」是兩端介面都設定了這個 VLAN 的鏈路數，不是檢查結果。
- **原文對話框**：標題寫出這一行所屬的「設備 › 指令（第 N 行）」，滑過看檔名與行號。長的行預設自動換行（接下去的部分縮排在行號之後）；取消勾選標題列的「自動換行」時不換行，在框內左右捲動。從檢查結果的證據或詳情的來源開啟時，若有多處，標題旁有「上一處」「下一處」與目前是第幾處，也可以按 ←、→ 切換（頭尾相接）。

## 搜尋與路由追蹤

- 上方的搜尋（按 / 開始；窄螢幕是工作區列右端的搜尋圖示）可以直接輸入設備名、MAC、IP、VLAN（`30`、`vlan 30` 或 `VLAN30`；以 0 開頭的數字不當成 VLAN）、介面名稱或描述。搜尋是「在圖上定位」：在 ④、⑤ 時會回到 ② 或 ③ 的拓樸圖。
  - **IP 前綴**：輸入開頭幾段（例如 `10.1.` 或 `10.1`），先列以它開頭的直連網段，再列 IP；點網段開啟網段詳細資料。
  - **MAC 前綴**：輸入開頭幾組十六進位（例如 `04:42`，分隔符可以是 `:`、`-`、`.` 或不寫）。只有數字時（例如 `10`、`10.1`）當成 VLAN ID 或 IP 前綴，不當成 MAC。
  - **介面名稱**：名稱含輸入文字的介面，副標寫出類型、狀態與描述；描述含輸入文字的介面也會列出。
- **IP 在多個 VRF**：搜尋的 IP 同時在多個 VRF（位址重疊）時，IP 詳情標出「在 N 個 VRF（位址重疊）」，並列出選擇表：每個 VRF 一列，寫出設定在哪裡、所屬網段與 ARP 筆數。點一列（或用 Tab 移到列上按 Enter、空白鍵）就只看那個 VRF：標題改成 `位址@VRF`（main 只寫位址），旁邊有「看所有 VRF」的連結可以回到選擇表。還沒選時，設定在與所屬網段只列在選擇表裡，下方不重複；ARP 紀錄多一欄 VRF。從清單、檢查結果或比對的 IP 點進來時，已經知道 VRF 的直接看那個 VRF。
  - 搜尋框下拉選單裡 IP 的副標也寫出 VRF：在多個 VRF 時寫「在 N 個 VRF：名稱、名稱」，最多列 4 個名稱，超過時以「…」結尾；只在一個非 main 的 VRF 時寫「VRF 名稱」；只在 main 時不寫 VRF。
- **路由追蹤**：從頁首的「⋯」→「路由追蹤…」開啟（IP 詳情的「從這個 IP 追蹤路由」也可以）。輸入來源與目的 IP（輸入時會提示基準中的 IP 與它所在的設備或介面），逐跳顯示（含 ECMP），同時列出回程並標示非對稱路徑，遇到黑洞路由會停下。路徑畫在拓樸圖上。按 Esc 或點視窗外面關閉，焦點回到「⋯」。
  - **無法驗證**：路徑走到未收集的設備時，那一支在那裡停下，結果列與圖上的那台設備是灰色的「無法驗證」：沒有它的路由表，不能判斷是否抵達，不算斷掉。沒有抵達、而且每一支都停在未收集的設備時，整體結果是「無法驗證（X 未收集）」；有一支沒有路由、黑洞、迴圈等時是錯誤色的「無法完整抵達」。
  - **VRF**：基準有兩個以上的 VRF 時，多一個「VRF」選單，預設「依來源位址決定」；只用 main 時沒有這個選單。來源位址在多個 VRF 時不猜，追蹤視窗留著並寫出有哪些 VRF，焦點移到選單，選好再按「追蹤」。從 IP 詳情按「從這個 IP 追蹤路由」時，已經選了 VRF（或這個 IP 只在一個 VRF）就預先選好。
  - 回程的 VRF：去程抵達的 VRF 只有一個時用那一個，否則用選單選的。
  - 有多個 VRF 時，詳情寫出這次的 VRF（指定，或依來源位址決定），每一跳標出它的 VRF，下一台設備寫出 `@VRF`；結果寫出在哪個 VRF 結束。
  - 每一跳另標出查的路由表（不是 VRF 的表時，也就是依 `/routing rule` 查的策略路由表）、經過的 VRF 介面，以及決定查表的 `/routing rule`（條件、動作、路由表與來源行）。下一跳的設備是依「對方在另一個 VRF、網段相同」找到的（crossVrf）時標「推論」。
  - 結束狀態多了「策略路由不明」（mark-routing、改過的 policy-rules 或無法判斷的 `/routing rule` 條件，查哪一張表不明）與「策略路由丟棄」（`/routing rule` 的 drop 或 unreachable），並列出相關的規則；有策略路由不明時，標題下方另標「策略路由不明」。

## 儲存與匯出

- 基準存在這個瀏覽器（IndexedDB），下次開啟自動還原；程式更新後若基準格式不同，會用儲存的輸入重新建立。
- 「⋯」→「清除基準…」只清除本工具儲存的基準與輸入（含載入的預期現況）；處理紀錄、版面寬度等設定不受影響。處理紀錄只存在這個瀏覽器，請定期在資料中心匯出，或匯出工作包保存。
- 所有匯出都在資料中心（[① 輸入](#step-input)）；頁首的「⋯」另有「匯出 PNG」。
  - 基準 JSON：目前的基準原樣下載，不改寫，可以留作之後「與舊基準比對」的舊基準。
  - CSV：UTF-8 含 BOM，Excel 可以直接開啟。除了檢查結果本身，另有處理紀錄的狀態、時間、備註、豁免原因與到期日、所屬設備與處理建議（照規則目錄原文，指令保留反引號）。舊版的確認欄位（`acknowledged`、`ack_kind`、`ack_note`）保留在原位置，改由處理紀錄對應。常見原因不放進 CSV，因為同一段文字會在每一列重複。欄位見[設計說明 §11.5](設計說明.md#115-匯出)。
  - Markdown：依規則分組時，每條規則先列處理建議與逐條的常見原因，指令寫成行內程式碼；依設備分組時，處理建議與常見原因集中在報表最後的「附錄：處理建議與常見原因」，每條規則只列一次。
  - 按下「依設備排序」後，CSV 依設備排序、Markdown 依設備分組。
  - devices.csv 草稿：由只被鄰居發現的網路設備（C01）產生 [SSH 批次收集](收集清單與輸入格式.md#0-批次-ssh-收集器wsllinux)用的設備清單。`user` 欄是佔位值 `CHANGE_ME`，使用前要改成實際的帳號；沒有位址或名稱不合規則等不能直接使用的設備寫成註解列，修正後移除開頭的 `#`。
  - 檔名含建立時間與設備數，例如 `findings-20260101T000000Z-42dev.csv`；工作包是 `workpack-<時間>-<N>dev.zip`。
