# 多層網路架構圖 實作規格書

> L2（VLAN／MAC＋L1）・L3（IP／Route）・L4（SLB＋ACL＋Service）　草案 v0.2（2026-10-20）

## 0. 文件狀態

v0.2 依 topo-mikrotik 的現況（Snapshot `ssot-snapshot/2`、`S.VERSION` 2.0.0）修訂。修訂方式如下：

- 原有需求全部保留，每項加上「本工具對應」與「狀態」。
- 與工具現行架構衝突的需求，改寫為可行的版本，原需求移到「範圍外」並說明原因。詳見 [§10](#10-與現行架構的衝突與決策)。

狀態代號：

| 代號 | 意義 |
|---|---|
| **已有** | 已實作，可在 Snapshot 或查詢介面取得 |
| **部分** | 已有一部分，缺口寫在說明欄 |
| **P1／P2／P3** | 規劃在第一、二、三階段實作，見 [§11](#11-實作階段) |
| **範圍外** | 本工具（MikroTik RouterOS 專用、離線、一次建立）不實作 |

本工具的資料來源只有 RouterOS CLI 輸出（`detail without-paging`），收集方式見 [collection.md](collection.md)。資料模型見 [design-ssot.md §5.2](design-ssot.md#52-實體snapshotmodelschema-ssot-snapshot2)，檢查規則見 [checks.md](checks.md)。

## 1. 範圍與設計原則

| 原則 | 說明 | 本工具對應 |
|----|----|----|
| 分三層、各一張圖 | L2、L3 為拓樸圖；L4 不畫成拓樸，改為 zone 矩陣＋查詢 | L2 拓樸圖已有；L3 圖 P2；L4 矩陣 P3 |
| 層間以錨點銜接 | L1 port ← MAC ← IP ← (IP, proto, port)，每層只往下一層對應 | 埠 ← MAC ← IP 已有（bridge host、ARP） |
| 存規則、不存結果 | 可達性於查詢時計算，不預算全對全矩陣 | 與現有「Snapshot 存事實、查詢時計算」一致 |
| 預設聚合、點選展開 | 主視圖以 zone 為單位，下鑽至 IP、port、路徑 | L2 圖已採用（終端群組收合、雙擊展開） |
| Workload 不在主流程 | 作為可選對應表，僅在端點需展開時查詢 | 範圍外 |
| 一次建立、可重現 | 同一份輸入一定得到同一份結果，不做增量合併 | v0.2 新增；沿用工具既有原則 |
| 可離線 | 不需後端與執行期網路連線；查詢為 JS 函式 | v0.2 新增；沿用工具既有原則 |

## 2. 共用資料模型

### 2.1 核心實體

| 實體 | 主鍵 | 主要欄位 | 所屬層 | 本工具對應 | 狀態 |
|----|----|----|----|----|----|
| Device | device_id | hostname, role(switch/router/fw/slb/host), vendor, mgmt_ip | 共用 | `devices`：`key`、`hostname`、`kind`、`manufacturer`、`mgmtIp`；`kind` 沒有 slb（RouterOS 無 SLB） | 已有 |
| Interface | (device_id, ifname) | type(phy/lag/svi/sub), admin/oper, mac, lag_parent | L1/L2 | `interfaces`：`type`（`physical`／`lag`／`vlan` 等）、`enabled`／`status`、`hwMac`、`lag` | 已有 |
| Link | (ifA, ifB) | source(lldp/cdp/gnmi/controller), last_seen | L1 | `links`：`protocols`（lldp／cdp／mndp）；`last_seen` 改為「設備收集時間」（取自 export 開頭的日期行） | 部分；收集時間 P1 |
| Vlan | (domain, vlan_id) | name, l2_domain | L2 | `vlans` 以設備內的 VLAN ID 為鍵；`l2_domain` 由鏈路兩端共同 VLAN 的連通元件推論（標示為推論） | 部分；l2_domain P2 |
| PortVlan | (ifname, vlan_id) | mode(access/trunk), native, allowed_list | L2 | 介面的 `mode`（access／tagged）、`pvid`（native）、`untaggedVlans`＋`taggedVlans`（allowed）；`frame-types`、`ingress-filtering` 未收集 | 已有；兩個設定 P1 |
| MacEntry | (device, vlan, mac) | ifname, type(dynamic/static), last_seen | L2 | `macs[].seen`（`{ep, vlan}`）；type 取自 bridge host 的 `D`（dynamic）旗標；RouterOS 沒有 age 欄位，`last_seen` 只能用設備收集時間 | 部分；type P1 |
| Vrf | (device, vrf) | rd, 對應 zone | L3 | 需收集 `/ip vrf`，以路由的 `routing-table`、`vrf-interface` 對應 | P2 |
| IpAddr | (vrf, ip) | prefix, ifname, role(primary/vip/hsrp/vrrp) | L3 | `ipAddresses`（已預留 `vrf`）；role 的 vrrp 由介面 `rawType=vrrp` 判定；hsrp 為 Cisco 專有，不適用 | 已有；role P1、vrf P2 |
| Subnet | (vrf, prefix) | gateway, vlan_id, zone_id | L3 | `prefixes`（直連網段，已預留 `vrf`）；gateway、vlan_id 由 VLAN 子介面的 `parent`＋`encapVlan` 推得 | 部分；gateway／vlan_id P1、zone P3 |
| ArpEntry | (device, vrf, ip) | mac, ifname | L3→L2 錨點 | `arps` | 已有；vrf P2 |
| Route | (device, vrf, prefix) | next_hop, out_if, protocol, AD, metric, ecmp_group | L3 | `routes`：`nh[]`（ECMP）、`proto`；AD 取 `distance`；黑洞路由目前被略過，P1 改為保留 | 部分；AD／黑洞 P1、vrf P2 |
| Zone | zone_id | name, type(dmz/db/mgmt/oa...), 來源(fw/vrf/tag/derived) | L4 | 由 `/interface list`、VRF、子網推導 | P3 |
| Rule | (acl_id, seq) | action, src/dst(obj ref), proto, port_range, stateful, hit_count | L4 | `/ip firewall filter`（export 已含）；hit_count 需 `print stats` | P3 |
| AclBinding | (device, ifname, dir) | acl_id, default_action | L4 | RouterOS 以 chain＋`in-interface`／`out-interface`（或 interface list）表達 | P3 |
| NatRule | (device, seq) | type(snat/dnat/pat), match, translate, 生效順序(pre/post filter) | L4 | `/ip firewall nat`；RouterOS 的 dstnat 在 filter 前、srcnat 在 filter 後 | P3 |
| SlbVip | (vip, proto, port) | pool_id, snat_mode, persistence | L4 | RouterOS 無 SLB | 範圍外 |
| PoolMember | (pool_id, ip, port) | weight, health | L4 | 同上 | 範圍外 |
| Service | (ns, ip, proto, port) | process, app_tag, 來源(ss/scan) | L4 | 需主機收集 | 範圍外 |
| RuleSet | hash | 正規化後的主機規則範本，主機只存參照 | L4 | 需主機收集 | 範圍外 |

### 2.2 跨層錨點

| 對應 | 來源資料 | 用途 | 狀態 |
|----|----|----|----|
| MAC → 交換器 port | MacEntry（排除 uplink/trunk 學到的 MAC） | 終端定位、L2 圖顯示端點 | 已有（終端埠判定，見 [checks.md A02](checks.md#a02)） |
| IP → MAC | ArpEntry | L3 節點接回 L2 位置 | 已有（`Q.findIp`） |
| IP:port → Service | Service | L4 比對終點 | 範圍外 |
| VIP → Pool member | SlbVip / PoolMember | L4 路徑分段 | 範圍外 |
| (ns, IP) → 宿主 | Workload（可選） | 主機 filter、Docker DNAT 歸屬 | 範圍外 |

唯一識別一律帶 VRF 或 namespace，以處理位址重疊。本工具在 P2 收集 VRF 前，所有位址與路由都視為 main 路由表。

## 3. L2 視圖（VLAN／MAC＋L1）

### 3.1 資料收集

| 項目 | 原方法 | 原頻率 | 本工具（RouterOS CLI） | 狀態 |
|----|----|----|----|----|
| 鄰居（L1） | SNMP LLDP-MIB / CDP-MIB、gNMI、控制器 API | 每日＋事件觸發 | `/ip neighbor print detail without-paging` | 已有 |
| LAG | IEEE8023-LAG-MIB、設定檔解析 | 每日 | export 的 `/interface bonding` | 已有（成員狀態 P1） |
| VLAN / trunk allowed | Q-BRIDGE-MIB、設定檔 | 每日 | export 的 bridge VLAN、`/interface bridge vlan print detail` | 已有 |
| MAC 表 | Q-BRIDGE-MIB dot1qTpFdb、CLI | 每 15–60 分 | `/interface bridge host print detail without-paging` | 已有 |

收集頻率：本工具是一次建立的離線基準，不排程收集。定期收集可用 `tools/collect.sh` 搭配外部排程，每次產生一份獨立的基準；不做跨次合併（見 [§10](#10-與現行架構的衝突與決策)）。

### 3.2 處理規則

| 規則 | 狀態 |
|----|----|
| 同一條線由兩端或控制器重複回報時合併為一條 Link | 已有（鏈路鍵與兩端無關） |
| LAG 成員收斂為一條邏輯鏈路，成員數與狀態作為屬性 | 部分：圖上已將同兩台設備的鏈路併成一條線；成員狀態 P1 |
| 端點定位：MAC 只在 access port（或非 uplink 的 port）出現才視為直連；同一 MAC 出現於多台交換器時取無 LLDP 鄰居的那個 port | 已有（終端埠：單一 MAC、無 LLDP／CDP 鄰接到已收集網路設備） |
| 一個 port 上 MAC 數超過門檻（如 \>5）標記為「下掛未管理交換器或 hypervisor」 | P1（新增檢查） |

### 3.3 呈現

| 元素 | 表示方式 | 狀態 |
|----|----|----|
| 容器 | 交換器／路由器，內含 port | P2（埠層級圖面；版面引擎 ELK 已支援 port） |
| 節點 | port；可展開顯示下掛端點（MAC/IP/hostname） | 部分：目前節點為設備，終端以「未知對端」節點顯示並可展開 |
| 連線 | 實體鏈路；LAG 加粗；顏色或標籤顯示 trunk allowed VLAN | 部分：LAG 有獨立類別線型；allowed VLAN 顯示在鏈路詳情 |
| 篩選 | 依 VLAN 篩選時，只亮出允許該 VLAN 的鏈路，即該 VLAN 的 L2 廣播網域 | 部分：`Q.vlan(id)` 已算出承載與部分承載的鏈路；圖上高亮 P2 |

### 3.4 檢查項目

| 檢查 | 狀態 |
|----|----|
| 兩端 trunk allowed VLAN 不一致、native VLAN 不一致 | 部分：V01 比較聯集；P1 拆成 allowed 與 native 兩項 |
| VLAN 存在於 SVI 但無任何 access port（孤立 VLAN） | P1 |
| 鏈路單端回報（鄰居表不對稱） | 已有（[K01](checks.md#k01)） |

## 4. L3 視圖（IP／Route）

### 4.1 資料收集

| 項目 | 原方法 | 本工具（RouterOS CLI） | 狀態 |
|----|----|----|----|
| 介面 IP、VRF | IP-MIB、設定檔、gNMI | export 的 `/ip address`、`/ip address print detail`；VRF 需 `/ip vrf` | IP 已有；VRF P2 |
| 路由表 | IP-FORWARD-MIB、CLI（show ip route vrf all）、gNMI AFT | `/ip route print detail without-paging`（目前只取 main 表） | 已有；其他路由表 P2 |
| ARP | IP-MIB ipNetToPhysical | `/ip arp print detail without-paging` | 已有 |
| 閘道 VIP | HSRP/VRRP MIB、設定檔 | export 的 `/interface vrrp`（RouterOS 只有 VRRP） | P1 |

### 4.2 處理規則

| 規則 | 狀態 |
|----|----|
| 子網依 (VRF, prefix) 建立，gateway 取 SVI 或 HSRP/VRRP VIP | 部分：`prefixes` 依 prefix 建立；VRF P2；gateway P1 |
| 跨子網的節點只取「有路由能力」的設備（有 forwarding、有路由表）；主機多網路卡不視為路由，避免誤判 | 已有（路徑追蹤只沿有路由表的設備前進） |
| 路徑計算：逐跳查 longest-prefix match，ECMP 展開為多條；結果存為 path 物件供 L4 繼承 | 已有（`src/query/trace.js`，含遞迴下一跳） |
| 非對稱路徑：提供 dst→src 反向路徑，供無狀態 ACL 檢查回程 | P1 |

### 4.3 呈現

| 元素 | 表示方式 | 狀態 |
|----|----|----|
| 容器 | VRF，內含子網 | P2 |
| 節點 | 子網；路由設備為跨子網的連接點 | P2 |
| 連線 | 路由器介面所連的子網；靜態路由／預設路由以虛線標示 | P2 |
| 查詢疊圖 | 輸入 src、dst，在圖上標出逐跳路徑（含 ECMP 分支） | 已有（在 L2 圖上疊圖） |

### 4.4 檢查項目

| 檢查 | 狀態 |
|----|----|
| 黑洞路由、路由迴圈、next-hop 不可達 | 部分：next-hop 不可達已有（[R01](checks.md#r01)）；迴圈偵測已在遞迴解析中，P1 產生檢查結果；黑洞路由 P1（需先保留黑洞路由） |
| 子網無閘道、閘道 IP 不在子網內 | P1 |
| ARP 中 IP 無對應子網（漂移或錯設） | P1 |

## 5. L4 視圖（SLB＋ACL＋Service）

本工具只實作 RouterOS 自身的防火牆與 NAT（P3）。SLB、主機、容器與雲端規則需要 RouterOS 以外的收集來源，列為範圍外（見 [§10](#10-與現行架構的衝突與決策)）。

### 5.1 資料收集

| 來源 | 內容 | 備註 | 狀態 |
|----|----|----|----|
| 網路設備 | ACL、object-group、介面綁定、NAT | 保留原始順序與群組參照 | P3：RouterOS 的 `/ip firewall filter`、`nat`、`address-list`、`/interface list`（export 已含） |
| 防火牆 | zone、policy、NAT、session 預設 | 有狀態 | P3：RouterOS 防火牆為有狀態（connection-state） |
| SLB | VIP、pool、SNAT 模式、health | VIP 視為 Service | 範圍外 |
| Linux 主機 | nft list ruleset / iptables-save、ss -lntu | SSH/Ansible 收集 | 範圍外 |
| Windows 主機 | Get-NetFirewallRule＋Port/AddressFilter、netstat | block 優先語意 | 範圍外 |
| 容器 / K8s | DOCKER/DOCKER-USER chain、NetworkPolicy | 需 Workload 對應 | 範圍外 |
| 雲端 | Security Group / NSG | 掛在 vNIC，視為主機規則 | 範圍外 |

### 5.2 規則正規化（P3）

- 統一為 Rule(seq, action, src_set, dst_set, proto, port_range,
  stateful)，錨點為 (device\|host, interface, in/out)。

- 不展開 object-group（RouterOS 為 address-list、interface list）；比對時用集合運算（BDD 或 interval set）。

- 每台設備標註語意：first-match／block-priority、預設 action、NAT 相對於
  filter 的順序。RouterOS 為 first-match；chain 結尾未命中時預設接受。

- 主機規則正規化後取 hash 存成 RuleSet，主機只存參照（範圍外）。

### 5.3 可達性計算（P3）

查詢 (src, dst, proto, port) 時：

- 取 L3 路徑；沿途依序套用各介面 in/out 的 AclBinding。

- 遇到 NAT/SLB：改寫位址，以新位址重新向 L3 取下一段路徑（本工具只處理 NAT）。

- 套用來源主機 OUTPUT、目的主機 INPUT（容器再加宿主 FORWARD）（範圍外）。

- 比對目的 Service；無狀態設備另檢查回程路徑（Service 範圍外）。

- 輸出：允許／拒絕、決定性規則、每段位址、是否有服務監聽。

### 5.4 Zone 定義（P3）

| 優先 | 來源 | 本工具對應 |
|----------|------------------------------------|----|
| 1 | 防火牆 zone、VRF | RouterOS `/interface list`、VRF |
| 2 | 子網／VLAN＋用途標籤 | `prefixes`、VLAN；用途標籤可由命名規則提供 |
| 3 | 規則等價類（用於驗證 1、2 的分組） | 規則正規化後計算 |

MGMT 獨立成 zone；SLB VIP 歸屬其所在 zone；zone 判斷以 NAT 後位址為準。

### 5.5 下鑽層級（P3）

| 層級 | 觸發 | 列 × 欄 | 格子內容 | 計算 |
|----|----|----|----|----|
| L0 | 主視圖 | src zone × dst zone | 全通/全擋/部分/異質；可切 service 類別 | 預算（建立基準時一併計算） |
| L1 | 點 zone 格 | src IP 群組 × dst IP | 允許 port 數或異質 | 即時 |
| L2 | 點 IP 格 | dst port 列表 | 允許/監聽/決定規則/差異狀態 | 即時 |
| L3 | 點 port | 路徑追蹤 | 逐段設備、命中規則、NAT/SLB 改寫、主機 filter | 即時 |

### 5.6 格子狀態定義（P3）

| 狀態 | 條件 |
|----------|-----------------------------------------------------------|
| 全通 | zone 內所有成員對該 service 類別允許 |
| 全擋 | 全部拒絕 |
| 部分 | 部分 IP 或 port 允許 |
| 異質 | 同 zone 成員的結果不一致（zone 切分錯誤或主機規則不一致） |
| 多開 | 允許但無服務監聽，或不在 Dependency 清單（需 Service 資料，範圍外） |
| 漏開 | 有服務監聽／有 Dependency，但被拒絕（需 Service 資料，範圍外） |

### 5.7 呈現規則（P3）

- L0 對角線（zone 內）單獨標示，主要受主機 filter 影響。

- L1 src 端合併結果相同的 IP 為群組；dst 保留個別 IP；全擋列欄預設隱藏。

- L2 連續允許的 port 合併為區間。

- 從「異質」格下鑽時，L1 預設只顯示造成差異的 IP。

- SLB/NAT：L1 顯示 VIP，L3 顯示改寫前後兩段（本工具只有 NAT）。

### 5.8 規則整理產出（P3）

- 被遮蔽規則（shadowed）、重複規則、永不命中規則（搭配 hit_count；需收集 `/ip firewall filter print stats`）。

- 過寬規則（any/any、port range 過大）。

- 主機 RuleSet 範本數量與偏離基準的主機清單（範圍外）。

## 6. 查詢介面

原規格為 HTTP API。本工具沒有後端，改為 `SSOT.query(snapshot)` 提供的 JS 函式，畫面與比對模組都透過它讀取資料。

| 原 API | 輸入 | 輸出 | 本工具對應 | 狀態 |
|----|----|----|----|----|
| /l2/locate | mac 或 ip | 交換器、port、VLAN | `Q.findMac(mac)`、`Q.findIp(ip)` | 已有 |
| /l3/path | src, dst, vrf | 逐跳路徑（含 ECMP） | `S.trace(Q, src, dst)`（`src/query/trace.js`） | 已有；vrf P2 |
| /l4/reach | src, dst, proto, port | 允許/拒絕、分段路徑、命中規則、Service | 規劃為 `Q.reach(...)` | P3（Service 範圍外） |
| /l4/matrix | level, filter(zone/ip/service) | 矩陣資料 | 規劃為 `Q.matrix(...)` | P3 |
| /l4/rule-impact | acl_id, seq | 受影響的 zone 對、是否遮蔽 | 規劃為 `Q.ruleImpact(...)` | P3 |

## 7. 資料量控制

| 手段 | 效果 | 本工具對應 |
|--------------------------|----------------------------|----|
| 不展開 object-group | 規則數維持原始量級 | P3 |
| 位址等價類 | 計算單位從主機數降至網段數 | P3 |
| RuleSet hash 去重 | 主機規則降至範本數 | 範圍外 |
| Service 只存角色基準差異 | 監聽清單大幅縮減 | 範圍外 |
| L0 預算、L1–L3 即時 | 儲存量與端點數約為線性 | P3（L0 在建立基準時計算） |
| 依設定變更做增量重算 | 只重算受影響的 zone 對 | 範圍外：與「一次建立」原則衝突，改為每次重建（約 1000 台約 3–4 秒） |

## 8. Workload 對應（可選，範圍外）

- 以 network namespace
  為單位攤平：宿主=路由器（filter/NAT），bridge/vSwitch=L2
  交換器，容器/VM=端點。

- 僅在 L4 查詢遇到主機端點且有對應時展開；無對應則視為單一端點。

- 虛擬化少的場域可完全不啟用。

本工具只收集 RouterOS 輸出，不實作 Workload 對應。

## 10. 與現行架構的衝突與決策

本工具的既有原則見 [design-ssot.md §2](design-ssot.md#2-原則)：一次建立、可重現、可離線、只吃 RouterOS 輸出。下列需求與之衝突，v0.2 先採「建議做法」，**待確認**。

| 原需求 | 衝突 | 建議做法（v0.2 採用） |
|----|----|----|
| 定期收集（每日、每 15–60 分）、`last_seen`、依設定變更增量重算 | 基準是一次建立的 Snapshot，沒有時間序列；增量合併違反可重現 | 每台設備記錄收集時間；需要歷史時保留多份基準，由日後的「基準差異比對」功能比較（見 [design-ssot.md §11](design-ssot.md#11-尚未做)） |
| SNMP、gNMI、控制器 API、多廠牌、Linux／Windows／K8s／雲端規則、SLB、Workload | 本工具是 MikroTik RouterOS 專用版，只吃 CLI 輸出 | 列為範圍外；需要時另建多來源版本（可參考多廠牌版 topo-ssot） |
| HTTP API（/l2/locate 等） | 無後端、可離線 | 以 `SSOT.query()` 的 JS 函式提供相同查詢 |

## 11. 實作階段

| 階段 | 內容 | 粗估 |
|----|----|----|
| P1：補齊 L2／L3 子集 | 設備收集時間、MAC 類型、`frame-types`／`ingress-filtering`、LAG 成員狀態、路由 distance 與黑洞路由、VRRP 角色、子網閘道與 vlan_id；新檢查：allowed／native 不一致、孤立 VLAN、單埠 MAC 過多、路由迴圈、黑洞路由、子網無閘道、閘道不在子網、ARP 無對應子網；反向路徑追蹤 | 1–2 週 |
| P2：VRF 與 L2 domain | 收集 `/ip vrf`、多路由表；位址、ARP、路由加上 VRF；L2 domain 推論；VLAN 篩選高亮；埠層級 L2 圖；L3 子網圖（VRF 容器） | 2–3 週 |
| P3：RouterOS L4 | 解析 firewall filter／nat／address-list／interface list；規則正規化與集合運算；沿路徑的可達性查詢（含 NAT 改寫）；zone 矩陣與下鑽；規則整理產出 | 4–6 週以上 |

時程為粗估。每個階段的新欄位與檢查，依專案流程同步 [design-ssot.md](design-ssot.md)、[checks.md](checks.md) 與測試。
