# 收集清單與輸入格式（MikroTik RouterOS）

基準的品質取決於輸入。這份文件規定「每台設備要下哪些指令」與「怎麼合併成一個收集檔」。

> **重要**：所有 `print` 指令都要加 **`detail without-paging`**。detail 的 `key=value` 格式在各版本間最一致，也不受欄寬影響；沒加 detail 的表格式輸出**不支援**，會列為「解析器已辨識，但解析不出內容」。

> **版本**：以 RouterOS 7.x 為主，6.43 以上（有 bridge VLAN filtering）大致可用。解析器依文件與慣例撰寫，**尚未用真實設備輸出驗證**，遇到無法解析的輸出請回報。

## 0. 批次 SSH 收集器（WSL/Linux）

專案提供輕量 Bash CLI，使用作業系統的 `ssh` 逐台執行以下唯讀指令，
最後產生一個可直接上傳網站的 `bundle-v1` 檔。它不在瀏覽器內執行，也不儲存
密碼或引入 SSH library。

前置條件：

- WSL/Linux、Bash、GNU `timeout` 與 OpenSSH client
- 已設定 SSH key/agent 與 known_hosts；不要把密碼寫進設備清單
- 先用 `ssh admin@<address>` 確認可免互動登入

設備清單使用 CSV，欄位為 `name,address,user,port[,extra]`；`port` 可省略，預設 22。
`extra` 選填，列出這台設備額外執行的選用命令 ID（以空白或分號分隔），用於只有部分設備才有的選單：

```csv
name,address,user,port,extra
TPE_CORE_RT_01,10.1.10.2,admin,22
TPE_ACC_SW_01,10.1.10.21,admin,22
TPE_AP_01,10.1.10.31,admin,22,wifi
```

可以從 repo 的範例複製一份，再把範例的文件保留 IP（`192.0.2.0/24`）改成實際位址：`cp tools/devices.csv devices.csv`。`name` 應唯一，建議與設備的 `/system identity` 相同（見 [§3](#3-設備名稱必須對得起來)）。

選用命令 ID 見下一節表格的「選用」列。用 `--commands` 指定命令時，只執行指定的命令，忽略 `extra`。

**自動加上的選用命令**：`extra` 欄留空、而且沒有使用 `--commands` 時，收集器依這台設備的輸出判斷要不要加收 Wi-Fi 關聯表，加上的命令排在這台設備區塊的最後執行：

- **主要依據 `/interface print` 的介面 type**（`interface` 收集成功時）：
  - 有 `type=wifi` 的介面時加 `wifi`，但 RouterOS 要 7.13 以上（版本取自 `/system resource print`）；7.13 之前這個選單在 wifiwave2 套件裡，收集器不支援，會印出略過原因。
  - 有 `type=wlan` 的介面時加 `wireless`，不限版本。
  - 兩種都有就兩個都加。這時不看型號決定要不要加，所以不會重複加，也不會因為型號在沒有無線介面的設備上誤加。
- **`interface` 收集失敗時，才退回型號規則**（`/system resource print` 的 `board-name`）：只有型號是 802.11ax／be（名稱中有 `ax`、`be` 字樣，例如 `cAP ax`、`hAP be lite`，或產品代碼的無線段，例如 `C52iG-5HaxD2HaxD-TC`），而且 RouterOS 是 7.13 以上時加 `wifi`；802.11ac、802.11n 的型號判斷不出用哪個套件，只印出略過原因。
- 終端機會寫出依據，例如 `AUTO wifi（interface type=wifi：wifi1, wifi2）`；看得出有無線、但不自動加時寫 `AUTO 略過（…）`。
- **限制**：舊版 CAPsMAN 控制器可以是任何型號、也沒有對應的介面 type，仍要在 `extra` 欄指定 `capsman`；7.12 以前的 wifiwave2 不支援。
- **依據**（官方手冊）：`type=wifi` 見 [REST API 的 `/interface/print` 範例](https://manual.mikrotik.com/docs/developer-guides/rest-api.md)，`type=wlan` 見 [CAPsMAN 的 `/interface print` 範例](https://manual.mikrotik.com/docs/wireless/abgn/capsman/ap-controller-capsman.md)，7.13 之前是 wifiwave2 見 [WiFi](https://manual.mikrotik.com/docs/wireless/wifi.md)，型號與無線標準的關係見 [Wireless](https://manual.mikrotik.com/docs/wireless.md)。
- `--no-auto` 關閉自動判斷。`--dry-run` 不連線，所以只列出依清單與 `extra` 決定的命令，**不含**自動加上的命令。

執行：

```bash
./tools/collect.sh devices.csv --output collection.txt
```

常用選項：

```bash
./tools/collect.sh devices.csv --dry-run
./tools/collect.sh devices.csv --device TPE_CORE_RT_01 --commands config,neighbor
./tools/collect.sh devices.csv --timeout 60 --retry 1 --output collection.txt
./tools/collect.sh devices.csv --ask-password
./tools/collect.sh devices.csv --no-auto
./tools/collect.sh devices.csv --commands config,neighbor,bridgehost,system --output topology.txt   # 只要基本 L2 拓樸
./tools/collect.sh devices.csv --commands config,fwfilter,fwnat,fwraw,fw6filter,fw6raw --output firewall.txt   # 只收防火牆（設定與命中次數）
```

沒有指定 `--commands` 時，執行預設清單的 17 個指令（2.10.0 以前是 12 個；新增的是防火牆命中次數的 5 個，見 [§1](#1-每台設備要收集的指令)），加上 `extra` 欄與自動加上的選用命令。沒有安裝 ipv6 套件的設備沒有 `/ipv6 firewall` 選單，`fw6filter`、`fw6raw` 會失敗（其他指令不受影響）；可以用 `--commands` 排除這兩個。

每次執行都會覆蓋輸出檔；要保留舊結果，請用 `--output`（`-o`）指定其他檔名。

`--ask-password` 供沒有設定 SSH key 的設備：每台設備先互動式連線一次（可輸入密碼、
確認 host key），其餘命令共用該連線，不會重複詢問；密碼不會寫入檔案或參數。
未使用此選項時，host key 需先用 `ssh user@address` 手動確認一次。

收集器預設使用 `BatchMode=yes`、逐台執行，失敗時會保留成功區塊並以非零
exit code 結束。每個指令的輸出前會寫入開始時間（`# collected-at:`），失敗時在輸出後寫入原因（`# collection failed:`），
建立基準時這些失敗會列在 C02 與覆蓋率的「有缺漏」，格式見 [§2「其他規則」](#其他規則)。請查看終端的設備/指令失敗摘要，不要把部分成功的檔案當成
完整基準。SSH stderr 不會混入 RouterOS stdout，也不會寫入輸出檔；設備 host
key 驗證交由系統 SSH，禁止用 `StrictHostKeyChecking=no`。

CLI 只執行本節列出的唯讀收集指令，不執行設定變更：收集指令只有 `/export` 和 `print`／`monitor … once`，不用 `reset-counters` 等會改設定或計數器的指令（`tests/collect.sh` 會檢查）。設備清單採用簡單 CSV
（每欄不可含逗號或引號）；輸出檔仍由網站正常走
reader、adapter、model 與 check pipeline；收集器不解析或修改 RouterOS 內容。

### 只重收失敗的指令

有指令失敗時，用 `--retry-failed` 讀上次的收集檔，只重收失敗的指令：

```bash
./tools/collect.sh devices.csv --retry-failed collection.txt -o collection-retry.txt
```

- **讀什麼**：上次收集檔中的 `# collection failed:` 紀錄（格式見 [§2「其他規則」](#其他規則)）。只重收這些設備的這些指令；連線資訊（位址、帳號、埠）仍取自設備清單。
- **合併規則**：輸出是合併後的新收集檔。失敗的區塊換成這次的結果，其他內容（含原本的 `# collected-at:`）逐字保留，所以建立基準時只要讀入新檔，不必連同舊檔一起讀入，也不會出現 I02。重收仍失敗時，該區塊寫入新的失敗紀錄。
- **連線失敗的設備**：上次是 `connection`（設備標頭之後就失敗）的設備，重收它的全部指令，含 `extra` 欄與自動加上的選用命令。
- **自動選用命令不重新判斷**：其他設備只重收上次有失敗紀錄的指令，不會因為這次的輸出另外加收 `wifi`、`wireless`。
- **`--ask-password` 時連不上**：設備沒有其他區塊時，照舊在設備標頭之後寫 `# collection failed: connection`；設備在上次收集檔已有其他區塊時，連線失敗寫在要重收的指令區塊內（`### 指令`、`# collected-at:`、`# collection failed: connection`），其他區塊保留。

選項組合：

| 選項 | 說明 |
|---|---|
| `-o FILE` | 必須指定，而且不可與上次的收集檔相同；上次的收集檔不會被修改 |
| `--device NAME,...` | 只重收這些設備的失敗。指定的設備在上次收集檔沒有失敗紀錄時報錯 |
| `--commands ID,...` | 只重收這些命令 ID 的失敗；連線失敗的設備也只收這些 ID。指定的 ID 在上次收集檔（選定的設備）沒有失敗紀錄時報錯 |
| `--dry-run` | 列出會重收的指令與上次失敗的原因，不連線，不需要 `-o` |
| `--timeout`、`--retry`、`--ask-password`、`--no-auto` | 照常適用；`--no-auto` 只影響連線失敗的設備 |

結束碼：

| 結束碼 | 情況 |
|---|---|
| 0 | 全部重收成功；或上次收集檔沒有任何失敗紀錄（印出「沒有需要重收的指令」，不產生輸出檔） |
| 1 | 合併後仍有失敗：重收仍然失敗，或有失敗不在 `--device`／`--commands` 的範圍內而沒有重收（終端機會列出筆數） |
| 2 | 無法重收：上次收集檔讀不到或格式不對（不是 `bundle-v1`、失敗紀錄不在設備區塊內、失敗的指令不是收集器的指令、有失敗紀錄的設備在檔中出現兩次以上）、有失敗紀錄的設備不在設備清單或位址與設備清單不同、`--device`／`--commands` 對不到失敗紀錄，或沒有指定 `-o`、`-o` 與上次的收集檔相同 |

## 1. 每台設備要收集的指令

| 資料類別 | 指令 | 用途 | 交換器 | 路由器 |
|---|---|---|:-:|:-:|
| 設定 | `/export terse`（`compact` 也可） | 介面註解、bridge、bridge VLAN、bonding、IP、router-id、主機名；跨設備一致性檢查用的 DHCP、DNS、NTP、address-list 等設定（見 [§1.1](#11-export-讀取的內容)） | 必要 | 必要 |
| 防火牆命中次數（`fwfilter`） | `/ip firewall filter print stats detail without-paging` | 每條規則的 bytes／packets（見下方「防火牆命中次數」） | 預設收集 | 預設收集 |
| 防火牆命中次數（`fwnat`） | `/ip firewall nat print stats detail without-paging` | 同上 | 預設收集 | 預設收集 |
| 防火牆命中次數（`fwraw`） | `/ip firewall raw print stats detail without-paging` | 同上 | 預設收集 | 預設收集 |
| 防火牆命中次數（`fw6filter`） | `/ipv6 firewall filter print stats detail without-paging` | 同上（沒有 ipv6 套件時會失敗，見 [§0](#0-批次-ssh-收集器wsllinux)） | 預設收集 | 預設收集 |
| 防火牆命中次數（`fw6raw`） | `/ipv6 firewall raw print stats detail without-paging` | 同上 | 預設收集 | 預設收集 |
| 鄰居 | `/ip neighbor print detail without-paging` | L2 鄰居證據（LLDP／CDP 介面鄰接；MNDP 同一 broadcast domain 可達） | 必要 | 必要 |
| MAC 表 | `/interface bridge host print detail without-paging` | MAC 位置 | 必要 | — |
| 路由表 | `/ip route print detail without-paging` | 路由追蹤 | 有 L3 時 | 必要 |
| ARP | `/ip arp print detail without-paging` | MAC↔IP | 建議 | 建議 |
| 系統資訊 | `/system resource print` | 型號（決定交換器／路由器）、版本 | 建議 | 建議 |
| Bridge VLAN 實際成員 | `/interface bridge vlan print detail without-paging` | 含動態成員（pvid 自動產生的項目） | 選用 | — |
| 介面狀態 | `/interface print detail without-paging` | running／停用／註解／原始 type／介面 MAC／MTU | 選用 | 選用 |
| IP 位址 | `/ip address print detail without-paging` | 含動態位址（DHCP client 等）；靜態的 export 已有 | 選用 | 選用 |
| OSPF 鄰居 | `/routing ospf neighbor print detail without-paging` | IP 層 L3 鄰接（不作為直連拓樸 edge） | 有跑 OSPF 時 | 有跑 OSPF 時 |
| RSTP 埠狀態 | `/interface bridge port monitor [find] once` | 每個埠的 STP 角色與指定橋接器；推論沒有 LLDP 的交換器（例如 CSS106、CSS610）接在哪個埠 | 建議 | 有 bridge 時 |
| RSTP bridge 狀態 | `/interface bridge monitor [find] once` | bridge 自己的 MAC、根橋接器 | 建議 | 有 bridge 時 |
| Wi-Fi 關聯表（選用 `wifi`） | `/interface wifi registration-table print detail without-paging` | Wi-Fi 客戶端關聯在哪個無線介面（RouterOS 7 wifi 套件） | — | — |
| Wi-Fi 關聯表（選用 `wireless`） | `/interface wireless registration-table print detail without-paging` | 同上（舊版 wireless 套件） | — | — |
| CAPsMAN 關聯表（選用 `capsman`） | `/caps-man registration-table print detail without-paging` | 同上，在舊版 CAPsMAN 控制器上一次取得所有 CAP 的客戶端 | — | — |

選用的 Wi-Fi 關聯表只在 AP 或 CAPsMAN 控制器上執行（設備清單的 `extra` 欄，或收集器依介面 type 自動判斷，見 [§0](#0-批次-ssh-收集器wsllinux)）：在沒有該選單的設備上執行會得到錯誤回應，整段列為 I01，訊息是「指令執行錯誤：<第一行>」。關聯表沒有客戶端時（只有說明行）視為已收集、0 筆。

**防火牆命中次數**（`fwfilter`、`fwnat`、`fwraw`、`fw6filter`、`fw6raw`）：

- **格式尚未確認**：官方手冊沒有 `print stats` 加 `detail` 的輸出範例，格式是依手冊推定，尚未以真實設備確認。解析器由 data-model 處理中；完成前讀入這些區塊會列為 I01（沒有任何解析器認得這段內容）。
- **必要程度**：預設收集；C02 的必要程度待 data-model 決定。
- **每個表一個指令**，不併進 `config`：一個 ID 對一個區塊，`--retry-failed` 才能單獨重收；某個表失敗也不會讓 `config` 變成失敗。
- **緊接在 `/export terse` 之後**：縮短 export 與計數器之間的時間，減少中間有人增刪規則而對不上的機會。
- 收集哪些表、不收哪些表，以及計數器怎麼對應到 export 的規則，見 [§1.1](#11-export-讀取的內容) 的末段。

**個資**：關聯表含 `eap-identity`、`eap-username`（802.1X 使用者帳號）。解析時刻意略過，不寫進基準；但收集檔保留原始輸出，畫面開啟原文時也看得到。收集檔請依個資規範保管。要分享或當測試資料時，用 `tools/anonymize.js` 去識別化（帳號、密碼、序號遮蔽，設備名、SSID、IP、MAC 換成代號但保留彼此關係），說明見 [tests/fixtures/real/README.md](../tests/fixtures/real/README.md)。

### 1.1 export 讀取的內容

`/export` 只讀取下列選單，其他選單（例如無線設定、VPN）不解析。這些內容都在原本的 `/export` 裡，不需要另外的收集指令。

| 選單 | 讀取的欄位 | 用途 |
|---|---|---|
| `/interface ethernet`、`/interface bridge`、`/interface bridge port`、`/interface bridge vlan`、`/interface vlan`、`/interface bonding`、`/interface vrrp` | 名稱、`comment`、停用、`vlan-filtering`、所屬 `bridge`、`pvid`、`frame-types`、`ingress-filtering`、`vlan-ids`、`tagged`／`untagged`、`vlan-id`、`slaves` | 介面、VLAN 與聚合 |
| `/ip address` | `address`、`interface`（略過停用） | 介面位址 |
| `/ip dhcp-server network` | `address`、`gateway`、`dns-server`、`ntp-server` | R05、R06 |
| `/ip firewall address-list` | `list`、`address` | A10、A11 |
| `/ip dns static` | `name`、`address`（只收 A／AAAA 紀錄，未寫 `type` 視為 A） | A10、A11 |
| `/ip pool` | `name`、`ranges` | A10、A11 |
| `/ip dhcp-server lease` | `mac-address`、`address` | A10、A11 |
| `/ip dns` | `servers`（唯讀的 `dynamic-servers` 不讀） | A12 |
| `/system ntp client` | RouterOS 7 為 `servers`；RouterOS 6 為 `primary-ntp`、`secondary-ntp` | A12 |
| `/system ntp client servers` | `address`（RouterOS 7 的子選單，每筆一個伺服器；略過停用項目） | A12 |
| `/system identity`、`/routing id`、`/routing ospf instance` | 主機名、router-id | 設備身分、OSPF 對應 |
| `/ip firewall filter`、`/ip firewall nat`、`/ip firewall raw`、`/ipv6 firewall filter`、`/ipv6 firewall raw` | 每條 `add` 的 `chain`、`action`、`disabled`、`comment`、比對條件（原樣保留，否定的 `!` 也保留）、動作參數（`jump-target`、`to-addresses`、`to-ports`、`reject-with`、`address-list`、`address-list-timeout`）；chain 內順序依出現順序 | F01–F08 |
| `/interface list`、`/interface list member` | 清單的 `name`、`include`、`exclude`；成員的 `list`、`interface`（略過停用） | WAN／LAN 分類（F03–F05、F07、F08） |
| `/ip service` | `set` 的服務名稱、`disabled`、`port`、`available-from`（舊版為 `address`） | F07 |
| `/ip ipsec peer`、`/ip ipsec policy` | peer 的 `name`、`address`、`disabled`；policy（`add`）的 `src-address`、`dst-address`、`peer`、`template`、`disabled` | F03（IPsec 放行是否需要） |
| `/ipv6 address`、`/ipv6 dhcp-client`、`/ipv6 settings` | 位址與 DHCPv6 client 的 `interface`（略過停用）；settings 的 `disable-ipv6=yes` | 判斷 IPv6 是否在用（F07 的 IPv6 部分） |

- address-list、DNS static、pool、DHCP lease 略過停用（`disabled=yes`）與動態（`dynamic=yes`）項目；`/system ntp client servers` 略過停用項目。
- DNS／NTP 伺服器的 `0.0.0.0`、`::`（RouterOS 6 的未設定值）視為沒有設定。
- 防火牆規則的註解中，RouterOS 以 `\XX` 寫出的非 ASCII 位元組依 UTF-8、Big5 解碼；都失敗時保留原文並標示為無法解碼。
- `/export` 只有設定的內容：沒寫的 `/ip service` 以 RouterOS 7 的出廠設定補上（待真機確認），動態規則（例如 UPnP 產生的 dst-nat）不在 export 裡，所以 F03、F04、F07 列出的可連入點不保證完整。目前不讀 `/ipv6 firewall nat`。
- **命中次數**不在 export 裡，由 `print stats` 另外收集（指令見 [§1](#1-每台設備要收集的指令)）：
  - 不含：動態規則（`print stats` 的 D 列，例如 FastTrack 的假規則、UPnP 產生的規則）、`/ip firewall mangle`、`/ipv6 firewall nat`。
  - 對應方式（規劃中，由解析器負責）：去掉 D 列後依序位對應 export 的規則，再用 `chain`、`action`、`disabled`、`comment` 驗證；對不上時，整個表都不配計數器。
  - 計數器是收集當下的累積值，可能被 reset 過；0 次不代表規則沒有用。

「必要」項目缺少時，檢查結果會出現 **C02 缺少應收集的資料**（判斷條件見[基準檢查規則 C02](基準檢查規則.md#c02)）。

**安全**：收集器的 `config` 命令執行 `/export terse`，不加 `show-sensitive` 也不加 `hide-sensitive`。RouterOS 7 的 `/export` 預設不輸出密碼、金鑰等機密參數（見官方手冊 [List of menus with sensitive parameters](https://manual.mikrotik.com/docs/getting-started/configuration-management/list-of-menus-with-sensitive-parameters.md)）。RouterOS 6.x 的 `/export` 有 `hide-sensitive` 選項（見 [6.43 的 changelog](https://download.mikrotik.com/routeros/6.43/CHANGELOG)），一般認為不加時會輸出這些機密，但這一點**尚未以官方文件確認**；請把 6.x 設備的收集檔當成含有密碼與金鑰處理。收集檔請自行保管；要分享或當測試資料前，先用 `tools/anonymize.js` 去識別化，並檢查輸出是否還有遺漏的機密（說明見上方「個資」）。

## 2. 收集檔格式（bundle-v1）

一個文字檔放所有設備。每台設備以標頭開始、以 `_____`（5 個以上底線）結束；分隔線可省略，遇到下一個標頭也會自動切段。

```
TPE_CORE_RT_01 (10.1.10.2):
[admin@TPE_CORE_RT_01] > /export terse
…輸出…
[admin@TPE_CORE_RT_01] > /ip neighbor print detail without-paging
…輸出…
_____
TPE_ACC_SW_01 (10.1.10.21):
### /interface bridge host print detail without-paging
…輸出…
_____
```

### 指令標記

每段輸出前要有一行標記指令，兩種寫法：

| 寫法 | 例子 |
|---|---|
| 明確標記（建議） | `### /ip neighbor print detail without-paging` |
| RouterOS 提示字元 | `[admin@TPE_SW_01] > /ip neighbor print detail without-paging` |

- 指令必須是**絕對路徑**（以 `/` 開頭）。`[admin@x] /ip> print` 這種相對路徑的提示字元不支援。
- RouterOS 7 的斜線路徑（`/interface/bridge/host/print`）視同空白分隔（`/interface bridge host print`），export 的選單路徑也一樣；提示字元可省略 `>`（官方手冊常見 `[admin@MikroTik] /interface/bridge/monitor bridge1`）。
- 沒有標記時，系統會依內容判斷是哪一種輸出；判斷不出來的段落列為 **I01 無法辨識的內容**，不會被丟掉。

### 其他規則

- 以單一 `#` 開頭的行是註解（`###` 才是指令標記），不會被解析。例外是 RouterOS export 開頭的 `# 日期 時間 by RouterOS 版本`：它是設備輸出的一部分，會讀成設備的收集時間（`devices[].collectedAt`，設備本地時間，沒有時區）。
- SSH 收集器另外寫兩種註解，讀進區塊、不交給解析器：
  - `# collected-at: <UTC ISO 8601>`：緊接在 `### 指令` 的下一行，代表這個指令開始執行的時間（收集器所在主機的 UTC 時間，秒精度，例如 `2026-10-24T03:00:00Z`），記在 `blocks[].collectedAt`。它和 export 開頭的時間不同：export 的是設備自己的本地時間、每台設備只有一個；collected-at 是每個指令各一個、一律 UTC。
  - `# collection failed: <原因>`：寫在該指令的輸出之後，原因為 `timeout` 或 `exit code N`；使用 `--ask-password` 而無法連線時，緊接在設備標頭之後寫 `connection`（這時沒有任何指令）；沒有使用 `--ask-password` 時，連不上的設備每個指令各記一次 `exit code N`（OpenSSH 連線失敗通常是 255）。例外：用 `--retry-failed --ask-password` 重收時，設備若已有其他區塊，`connection` 寫在重收的指令區塊內（見 [§0「只重收失敗的指令」](#只重收失敗的指令)）。記在 `blocks[].failure`，並列入 C02 與覆蓋率的「有缺漏」。
  - 這兩種註解格式或位置不對（時間不是 UTC ISO 8601、collected-at 不在指令標記的下一行、同一段有第二個失敗註解）時列為 **I01**，不會被靜默略過。只有註解、沒有指令與內容的段落（例如連線失敗）本身不算 I01。
- 同一台設備的同一種資料出現兩次時，採用**最後一次**，並列出 **I02**。
- 也可以一個檔案一台設備（`files-v1`）：檔名（去副檔名）就是設備名，內容同樣用指令標記分段。
- 同時貼上與選擇多個檔案時，會一次全部讀入建立同一份基準。

## 3. 設備名稱必須對得起來

- 標頭的設備名（`TPE_CORE_RT_01 (…)`）建議與 `/system identity` 相同；其他設備的鄰居列會用 identity 稱呼它。
- 若兩者不同，系統會用**管理 IP**對回同一台（標頭的 IP 要等於該設備在鄰居列中的 `address`）；都對不上就會被當成兩台不同的設備。
- 鄰居的 identity 若帶網域，可在命名規則加上 `"stripDomain": true`；其他對不上的用 `alias`。

## 3.1 沒有 LLDP 的設備（SwOS 交換器等）

CSS106、CSS610 等 SwOS／SwOS Lite 交換器**不支援 LLDP，也沒有 SSH／CLI**，收集器無法收集它們。它們在基準裡會是「僅由鄰居發現」的設備，和相鄰 RouterOS 的鏈路由「推論鏈路」推定（規則見[設計說明 §5.3](設計說明.md#53-關鍵推論)）。要讓推論成立：

1. **在 SwOS 開啟 MNDP**：System 頁的「Mikrotik Discovery Protocol」。相鄰的 RouterOS 才會在鄰居表看到它，並知道它的 MAC。
2. **每台 SwOS 交換器設定不重複的 identity**：用型號當名稱（例如都叫 CSS610-8P-2S+）會分不出是哪一台。
3. **相鄰的 RouterOS 要收 MAC 表**（`/interface bridge host`，本來就是交換器的必要資料）、介面狀態（`/interface print`，提供介面 MAC），以及 RSTP 狀態（`/interface bridge port monitor`、`/interface bridge monitor`）。SwOS 交換器也要啟用 RSTP：它在上游時，RouterOS 埠的指定橋接器會直接指出它，而且不受 MAC 表老化影響。MAC 表要有足夠流量才完整，建議在業務時段收集。
4. 終端接在 SwOS 交換器上時，只能由上一跳 RouterOS 的 MAC 表推定「在哪台 SwOS 交換器底下」，**埠不明**。兩台以上 SwOS 串接時，只能推定「在其中某一台或其下游」。
5. 同一個 /24 管理網段**無法**證明誰接誰；介面描述只寫型號也無法分辨。要用描述輔助時，請寫成能唯一識別的格式，例如 `to:CSS-3F-01 port1`。

## 4. RouterOS 特有的行為與限制

| 項目 | 說明 |
|---|---|
| 對端埠名 | LLDP 的 `interface-name` 可作為對端埠名證據。沒有時，單一鄰接仍可配對；**平行鏈路（例如 LACP）會依本機介面名稱排序後一一配對**，這是推測，不保證正確。MNDP 回報的 `interface-name` 只保留為鄰居回報值，不據此推論直連埠對 |
| MNDP 範圍 | 只有 MNDP 證據時，edge 表示兩台設備透過同一 L2 broadcast domain 可達，不代表兩台設備之間有直連實體線路（參見 [RouterOS Neighbor Discovery 手冊](https://manual.mikrotik.com/docs/system-information-and-utilities/neighbor-discovery.md)）。由此不檢查 K01 單向直連、K02 同介面多個直連鄰居、聚合成員配對或對端埠 VLAN 差異；來源介面與回報資料仍可追溯。資料沒有可識別的 broadcast-domain ID，因此不推論該廣播網域的完整成員清單 |
| 同一鄰居多列 | 同一台鄰居可能同時從連接埠與 `bridge` 出現，或被多個協定各列一次；系統優先採用連接埠，重複的丟掉。同一本機介面上 MAC 或 identity 相同的列（例如 LLDP 與 MNDP／CDP）會合併為一筆：`discovered-by` 取聯集（鏈路的 `protocols`），欄位取非空值，對端埠名優先採 LLDP；同一介面回報不同埠名時保留在 claim 的 `peerIfcAlt`。若合併列含 LLDP／CDP，保留介面鄰接推論；只有 MNDP 時按上列處理 |
| Bridge VLAN | 只有 bridge 開了 `vlan-filtering=yes` 才計入 VLAN 成員；每個 bridge 連接埠的 `pvid`（預設 1）記在介面的 `pvid`，並算是該 VLAN 的未標記成員；`tagged`／`untagged` 分別記在介面的 `taggedVlans`／`untaggedVlans`。bridge 開了 vlan-filtering 與否，連接埠都會記錄所屬 `bridge`。vlan-filtering 由 export 判斷，terse 不寫代表 no；未過濾的 bridge 不比較 VLAN，改報 [V09](基準檢查規則.md#v09) |
| VLAN 名稱 | RouterOS 的 bridge VLAN 沒有名稱欄位；跨設備比較的是 VLAN 介面的名稱、說明與 bridge VLAN 的說明（`comment`），見 [V06](基準檢查規則.md#v06)、[V07](基準檢查規則.md#v07) |
| 聚合 | `/interface bonding` 的 `slaves` 視為聚合成員（成員介面的 `lag`、聚合介面的 `lagMembers`），兩端成員數不同會列為 K03 |
| 設備類型 | 依型號：CRS／CSS 為交換器、CCR／RB／hAP／hEX／CHR 為路由器；沒有型號時，已收集的設備看有哪些資料，未收集的設備看鄰居回報的功能（`system-caps-enabled`） |
| 防火牆 | 規則與設定來自既有的 `/export`，不需要另外的收集指令：解析 filter、nat、raw（IPv6 為 filter、raw）、interface list、`/ip service`、IPsec peer／policy，供 F01–F08；`/ip firewall address-list` 的項目另供 A10、A11 跨設備比較。WAN／LAN 只由名稱含 `WAN`／`LAN` 的 interface list 推論。不含動態規則（例如 UPnP）。命中次數由 `print stats` 另外收集（解析器處理中），不含動態規則、`/ip firewall mangle` 與 `/ipv6 firewall nat`（見 [§1.1](#11-export-讀取的內容) 的末段） |
| Wi-Fi 客戶端位置 | 依證據強度推定，信心由高到低：①關聯表（已確認；同一 MAC 在多台 AP 時取 `last-activity` 最近者，其餘列為候選並標示可能漫遊）②已收集 AP 的 MAC 表在無線介面學到 ③交換器埠的鄰居是 AP（回報 `wlan-ap` 功能，或型號為 cAP／wAP）而 AP 沒有收集資料，此時無法區分有線或無線。已判定為有線終端埠的 MAC、AP 自己的 MAC 不套用 ③。結果在 MAC 詳情的「Wi-Fi 位置」，並標示依據 |
| CAPsMAN 的 CAP 對應 | 控制器的關聯表會把客戶端記在控制器上的 CAP 介面；CAP 介面對應到哪台實體 AP 尚未解析（需實機輸出驗證） |
| 無線設定、VPN | 不解析（只解析關聯表） |
