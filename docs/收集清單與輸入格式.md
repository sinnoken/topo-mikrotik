# 收集清單與輸入格式（MikroTik RouterOS）

基準的品質取決於輸入。這份文件規定「每台設備要下哪些指令」與「怎麼合併成一個收集檔」。

> **重要**：所有 `print` 指令都要加 **`detail without-paging`**。detail 的 `key=value` 格式在各版本間最一致，也不受欄寬影響；沒加 detail 的表格式輸出**不支援**，會列為「解析器已辨識，但解析不出內容」。

> **版本**：以 RouterOS 7.x 為主，6.43 以上（有 bridge VLAN filtering）大致可用。解析器依文件與慣例撰寫，**尚未用真實設備輸出驗證**，遇到無法解析的輸出請回報。

## 0. 批次 SSH 收集器（WSL/Linux）

專案提供輕量 Bash CLI，使用作業系統的 `ssh` 逐台執行以下唯讀指令，
最後產生一個可直接上傳網站的 `bundle-v1` 檔。它不在瀏覽器內執行，也不儲存
密碼或引入 SSH library。

前置條件：

- WSL/Linux、Bash、GNU `timeout` 與 OpenSSH client
- 已設定 SSH key/agent 與 known_hosts；不要把密碼寫進設備清單
- 先用 `ssh admin@<address>` 確認可免互動登入

設備清單使用 CSV，欄位為 `name,address,user,port[,extra]`；`port` 可省略，預設 22。
`extra` 選填，列出這台設備額外執行的選用命令 ID（以空白或分號分隔），用於只有部分設備才有的選單：

```csv
name,address,user,port,extra
TPE_CORE_RT_01,10.1.10.2,admin,22
TPE_ACC_SW_01,10.1.10.21,admin,22
TPE_AP_01,10.1.10.31,admin,22,wifi
```

選用命令 ID 見下一節表格的「選用」列。用 `--commands` 指定命令時，只執行指定的命令，忽略 `extra`。

執行：

```bash
./tools/collect.sh devices.csv --output collection.txt
```

常用選項：

```bash
./tools/collect.sh devices.csv --dry-run
./tools/collect.sh devices.csv --device TPE_CORE_RT_01 --commands config,neighbor
./tools/collect.sh devices.csv --timeout 60 --retry 1 --output collection.txt
./tools/collect.sh devices.csv --ask-password
```

`--ask-password` 供沒有設定 SSH key 的設備：每台設備先互動式連線一次（可輸入密碼、
確認 host key），其餘命令共用該連線，不會重複詢問；密碼不會寫入檔案或參數。
未使用此選項時，host key 需先用 `ssh user@address` 手動確認一次。

收集器預設使用 `BatchMode=yes`、逐台執行，失敗時會保留成功區塊並以非零
exit code 結束。請查看終端的設備/指令失敗摘要，不要把部分成功的檔案當成
完整基準。SSH stderr 不會混入 RouterOS stdout，也不會寫入輸出檔；設備 host
key 驗證交由系統 SSH，禁止用 `StrictHostKeyChecking=no`。

CLI 只執行本節列出的唯讀收集指令，不執行設定變更。設備清單採用簡單 CSV
（每欄不可含逗號或引號）；輸出檔仍由網站正常走
reader、adapter、model 與 check pipeline；收集器不解析或修改 RouterOS 內容。

## 1. 每台設備要收集的指令

| 資料類別 | 指令 | 用途 | 交換器 | 路由器 |
|---|---|---|:-:|:-:|
| 設定 | `/export terse`（`compact` 也可） | 介面註解、bridge、bridge VLAN、bonding、IP、router-id、主機名 | 必要 | 必要 |
| 鄰居 | `/ip neighbor print detail without-paging` | L2 鄰居證據（LLDP／CDP 介面鄰接；MNDP 同一 broadcast domain 可達） | 必要 | 必要 |
| MAC 表 | `/interface bridge host print detail without-paging` | MAC 位置 | 必要 | — |
| 路由表 | `/ip route print detail without-paging` | 路由追蹤 | 有 L3 時 | 必要 |
| ARP | `/ip arp print detail without-paging` | MAC↔IP | 建議 | 建議 |
| 系統資訊 | `/system resource print` | 型號（決定交換器／路由器）、版本 | 建議 | 建議 |
| Bridge VLAN 實際成員 | `/interface bridge vlan print detail without-paging` | 含動態成員（pvid 自動產生的項目） | 選用 | — |
| 介面狀態 | `/interface print detail without-paging` | running／停用／註解／原始 type／介面 MAC／MTU | 選用 | 選用 |
| IP 位址 | `/ip address print detail without-paging` | 含動態位址（DHCP client 等）；靜態的 export 已有 | 選用 | 選用 |
| OSPF 鄰居 | `/routing ospf neighbor print detail without-paging` | IP 層 L3 鄰接（不作為直連拓樸 edge） | 有跑 OSPF 時 | 有跑 OSPF 時 |
| RSTP 埠狀態 | `/interface bridge port monitor [find] once` | 每個埠的 STP 角色與指定橋接器；推論沒有 LLDP 的交換器（例如 CSS106、CSS610）接在哪個埠 | 建議 | 有 bridge 時 |
| RSTP bridge 狀態 | `/interface bridge monitor [find] once` | bridge 自己的 MAC、根橋接器 | 建議 | 有 bridge 時 |
| Wi-Fi 關聯表（選用 `wifi`） | `/interface wifi registration-table print detail without-paging` | Wi-Fi 客戶端關聯在哪個無線介面（RouterOS 7 wifi 套件） | — | — |
| Wi-Fi 關聯表（選用 `wireless`） | `/interface wireless registration-table print detail without-paging` | 同上（舊版 wireless 套件） | — | — |
| CAPsMAN 關聯表（選用 `capsman`） | `/caps-man registration-table print detail without-paging` | 同上，在舊版 CAPsMAN 控制器上一次取得所有 CAP 的客戶端 | — | — |

選用的 Wi-Fi 關聯表只在 AP 或 CAPsMAN 控制器上執行（設備清單的 `extra` 欄）：在沒有該選單的設備上執行會得到錯誤回應，列為 I01。關聯表沒有客戶端時（只有說明行）視為已收集、0 筆。

**個資**：關聯表含 `eap-identity`、`eap-username`（802.1X 使用者帳號）。解析時刻意略過，不寫進基準；但收集檔保留原始輸出，畫面開啟原文時也看得到。收集檔請依個資規範保管。要分享或當測試資料時，用 `tools/anonymize.js` 去識別化（帳號、密碼、序號遮蔽，設備名、SSID、IP、MAC 換成代號但保留彼此關係），說明見 [tests/fixtures/real/README.md](../tests/fixtures/real/README.md)。

「必要」項目缺少時，檢查結果會出現 **C02 缺少應收集的資料**（判斷條件見[基準檢查規則 C02](基準檢查規則.md#c02)）。

**安全**：不要使用 `show-sensitive`。RouterOS 7 的 `/export` 預設不輸出密碼與金鑰（6.x 請用 `hide-sensitive`）。收集檔只應包含拓樸資訊。

## 2. 收集檔格式（bundle-v1）

一個文字檔放所有設備。每台設備以標頭開始、以 `_____`（5 個以上底線）結束；分隔線可省略，遇到下一個標頭也會自動切段。

```
TPE_CORE_RT_01 (10.1.10.2):
[admin@TPE_CORE_RT_01] > /export terse
…輸出…
[admin@TPE_CORE_RT_01] > /ip neighbor print detail without-paging
…輸出…
_____
TPE_ACC_SW_01 (10.1.10.21):
### /interface bridge host print detail without-paging
…輸出…
_____
```

### 指令標記

每段輸出前要有一行標記指令，兩種寫法：

| 寫法 | 例子 |
|---|---|
| 明確標記（建議） | `### /ip neighbor print detail without-paging` |
| RouterOS 提示字元 | `[admin@TPE_SW_01] > /ip neighbor print detail without-paging` |

- 指令必須是**絕對路徑**（以 `/` 開頭）。`[admin@x] /ip> print` 這種相對路徑的提示字元不支援。
- RouterOS 7 的斜線路徑（`/interface/bridge/host/print`）視同空白分隔（`/interface bridge host print`），export 的選單路徑也一樣；提示字元可省略 `>`（官方手冊常見 `[admin@MikroTik] /interface/bridge/monitor bridge1`）。
- 沒有標記時，系統會依內容判斷是哪一種輸出；判斷不出來的段落列為 **I01 無法辨識的內容**，不會被丟掉。

### 其他規則

- 以單一 `#` 開頭的行是註解（`###` 才是指令標記），不會被解析。例外是 RouterOS export 開頭的 `# 日期 時間 by RouterOS 版本`：它是設備輸出的一部分，會讀成設備的收集時間（設備本地時間）。
- 同一台設備的同一種資料出現兩次時，採用**最後一次**，並列出 **I02**。
- 也可以一個檔案一台設備（`files-v1`）：檔名（去副檔名）就是設備名，內容同樣用指令標記分段。
- 同時貼上與選擇多個檔案時，會一次全部讀入建立同一份基準。

## 3. 設備名稱必須對得起來

- 標頭的設備名（`TPE_CORE_RT_01 (…)`）建議與 `/system identity` 相同；其他設備的鄰居列會用 identity 稱呼它。
- 若兩者不同，系統會用**管理 IP**對回同一台（標頭的 IP 要等於該設備在鄰居列中的 `address`）；都對不上就會被當成兩台不同的設備。
- 鄰居的 identity 若帶網域，可在命名規則加上 `"stripDomain": true`；其他對不上的用 `alias`。

## 3.1 沒有 LLDP 的設備（SwOS 交換器等）

CSS106、CSS610 等 SwOS／SwOS Lite 交換器**不支援 LLDP，也沒有 SSH／CLI**，收集器無法收集它們。它們在基準裡會是「僅由鄰居發現」的設備，和相鄰 RouterOS 的鏈路由「推論鏈路」推定（規則見[設計說明 §5.3](設計說明.md#53-關鍵推論)）。要讓推論成立：

1. **在 SwOS 開啟 MNDP**：System 頁的「Mikrotik Discovery Protocol」。相鄰的 RouterOS 才會在鄰居表看到它，並知道它的 MAC。
2. **每台 SwOS 交換器設定不重複的 identity**：用型號當名稱（例如都叫 CSS610-8P-2S+）會分不出是哪一台。
3. **相鄰的 RouterOS 要收 MAC 表**（`/interface bridge host`，本來就是交換器的必要資料）、介面狀態（`/interface print`，提供介面 MAC），以及 RSTP 狀態（`/interface bridge port monitor`、`/interface bridge monitor`）。SwOS 交換器也要啟用 RSTP：它在上游時，RouterOS 埠的指定橋接器會直接指出它，而且不受 MAC 表老化影響。MAC 表要有足夠流量才完整，建議在業務時段收集。
4. 終端接在 SwOS 交換器上時，只能由上一跳 RouterOS 的 MAC 表推定「在哪台 SwOS 交換器底下」，**埠不明**。兩台以上 SwOS 串接時，只能推定「在其中某一台或其下游」。
5. 同一個 /24 管理網段**無法**證明誰接誰；介面描述只寫型號也無法分辨。要用描述輔助時，請寫成能唯一識別的格式，例如 `to:CSS-3F-01 port1`。

## 4. RouterOS 特有的行為與限制

| 項目 | 說明 |
|---|---|
| 對端埠名 | LLDP 的 `interface-name` 可作為對端埠名證據。沒有時，單一鄰接仍可配對；**平行鏈路（例如 LACP）會依本機介面名稱排序後一一配對**，這是推測，不保證正確。MNDP 回報的 `interface-name` 只保留為鄰居回報值，不據此推論直連埠對 |
| MNDP 範圍 | 只有 MNDP 證據時，edge 表示兩台設備透過同一 L2 broadcast domain 可達，不代表兩台設備之間有直連實體線路（參見 [RouterOS Neighbor Discovery 手冊](https://manual.mikrotik.com/docs/system-information-and-utilities/neighbor-discovery.md)）。由此不檢查 K01 單向直連、K02 同介面多個直連鄰居、聚合成員配對或對端埠 VLAN 差異；來源介面與回報資料仍可追溯。資料沒有可識別的 broadcast-domain ID，因此不推論該廣播網域的完整成員清單 |
| 同一鄰居多列 | 同一台鄰居可能同時從連接埠與 `bridge` 出現，或被多個協定各列一次；系統優先採用連接埠，重複的丟掉。同一本機介面上 MAC 或 identity 相同的列（例如 LLDP 與 MNDP／CDP）會合併為一筆：`discovered-by` 取聯集（鏈路的 `protocols`），欄位取非空值，對端埠名優先採 LLDP；同一介面回報不同埠名時保留在 claim 的 `peerIfcAlt`。若合併列含 LLDP／CDP，保留介面鄰接推論；只有 MNDP 時按上列處理 |
| Bridge VLAN | 只有 bridge 開了 `vlan-filtering=yes` 才計入 VLAN 成員；每個 bridge 連接埠的 `pvid`（預設 1）記在介面的 `pvid`，並算是該 VLAN 的未標記成員；`tagged`／`untagged` 分別記在介面的 `taggedVlans`／`untaggedVlans`。bridge 開了 vlan-filtering 與否，連接埠都會記錄所屬 `bridge` |
| VLAN 名稱 | RouterOS 的 bridge VLAN 沒有名稱，所以沒有「同一 VLAN 名稱不同」這類檢查 |
| 聚合 | `/interface bonding` 的 `slaves` 視為聚合成員（成員介面的 `lag`、聚合介面的 `lagMembers`），兩端成員數不同會列為 K03 |
| 設備類型 | 依型號：CRS／CSS 為交換器、CCR／RB／hAP／hEX／CHR 為路由器；沒有型號時，已收集的設備看有哪些資料，未收集的設備看鄰居回報的功能（`system-caps-enabled`） |
| 防火牆 | 不解析防火牆規則 |
| Wi-Fi 客戶端位置 | 依證據強度推定，信心由高到低：①關聯表（已確認；同一 MAC 在多台 AP 時取 `last-activity` 最近者，其餘列為候選並標示可能漫遊）②已收集 AP 的 MAC 表在無線介面學到 ③交換器埠的鄰居是 AP（回報 `wlan-ap` 功能，或型號為 cAP／wAP）而 AP 沒有收集資料，此時無法區分有線或無線。已判定為有線終端埠的 MAC、AP 自己的 MAC 不套用 ③。結果在 MAC 詳情的「Wi-Fi 位置」，並標示依據 |
| CAPsMAN 的 CAP 對應 | 控制器的關聯表會把客戶端記在控制器上的 CAP 介面；CAP 介面對應到哪台實體 AP 尚未解析（需實機輸出驗證） |
| 無線設定、VPN | 不解析（只解析關聯表） |
