# ADR-004：無法辨識的行另列為 I03，不擴充 I01

- **狀態**：已接受
- **日期**：2026-10-24
- **決策者**：使用者

## 背景

I01 只處理「整個區塊沒有進入基準」的情況：沒有設備標頭、沒有解析器認得、認得但解析不出任何內容，或收集器註解的格式、位置不對。

已經解析的區塊中，個別認不得的行原本會被靜默略過，違反開發原則第 4 條「不靜默失敗」。測試中整理出的例子有：export 中夾了其他文字、`/ip arp` 輸出後接了其他文字、`/ip neighbor` 輸出後接 RouterOS 的錯誤訊息。

## 決策

- [src/adapters/index.js](../../src/adapters/index.js) 的 `S.adapters.parse` 檢查已解析區塊中的每個非空行。每一行要嘛產生事實（`fact.line`），要嘛由 adapter 以 `ignore(line, why)` 宣告依格式本來就不產生事實（說明行、續行、停用的項目等）。兩者都不是，就列入區塊的 `unrecognizedLines`。
- 有 `unrecognizedLines` 的區塊產生一筆 **I03**（警告，[src/check/checks.js](../../src/check/checks.js)）：訊息列出前 3 行的原文，證據是每一行。同一區塊其他已解析的內容照常進入基準。
- 整個區塊都認不得時仍是 I01，不重複列 I03。
- **RouterOS 錯誤訊息歸在 I03**：
  - 行首符合 `ROS_ERROR`（`bad command name`、`syntax error`、`expected end of command`、`no such item`、`failure:` 等）的行，**即使 adapter 列為可忽略，也一律算無法辨識**。像 `/system resource print` 這種 `key: value` 格式，錯誤訊息很容易被當成一般的行略過，所以不能交給各 adapter 判斷。
  - 錯誤訊息出現在已解析的區塊中，代表這個區塊有一部分已進入基準，但指令可能沒有完整執行。它和「混入的文字」一樣是「這幾行沒有進入基準」，差別在於後果更嚴重，所以 I03 訊息另外註明錯誤訊息的行數與第一行，提醒資料可能不完整。

## 考慮過的選項

| 選項 | 優點 | 缺點 | 結論 |
|---|---|---|---|
| A. 擴充 I01 的條件 | 不新增規則 | I01 是錯誤、代表整段沒進基準；I03 的其他內容已進基準。嚴重度、處理方式不同，放在同一條規則，處理紀錄與統計也分不開 | 不採用 |
| B. 新增 I03 | 嚴重度與處理方式各自明確；證據逐行列出 | 多一條規則要維護 | **採用** |
| C. 只記在區塊的 `unrecognizedLines`，不產生 finding | 畫面不多一筆 | 使用者不會注意到，等於靜默略過 | 不採用 |
| D. 各 adapter 自行回報認不得的行 | 不需要共用機制 | 每個 adapter 都要寫，漏寫就靜默略過 | 不採用；改為 adapter 只宣告可忽略的行，其餘一律列出 |
| E. 另外新增 I04「RouterOS 指令錯誤」 | 可以設不同嚴重度（例如錯誤）、分開統計與處理 | 同一行不能同時是 I03 與 I04，要定義互斥；現在沒有真實設備的資料可以評估出現頻率 | 暫不採用，見「之後要回頭看的」 |

## 後果

### 變容易的

- 每一行輸入都有去處：產生事實、可忽略、I03 或 I01。`tests/run.js` 以範例資料與 `tests/fixtures/` 的每個檔案檢查這一點。
- 解析器沒處理到的格式會自己浮現，成為改進解析器的線索（見 [ADR-011](011-I03轉成fixture的回歸流程.md)）。

### 變困難的

- 新增或修改 adapter 時，每一種不產生事實的行都要以 `ignore(line, why)` 宣告，否則會出現 I03。
- I03 的實體只有設備，同一台設備的多段 I03 共用同一個 findingKey（見 [ADR-003](003-findingKey的組成.md)）。

### 之後要回頭看的

- **I04**：開始用真實設備後，若 RouterOS 錯誤訊息常見，而且使用者需要和一般的無法辨識分開處理（不同嚴重度、不同豁免），再評估把錯誤訊息獨立成 I04。屆時要說明舊 I03 項目在處理紀錄中的轉換方式。
- **整段只有錯誤訊息的區塊**：這種區塊沒有任何事實，會列為 I01「解析不出任何內容」，處理建議是「print 指令請加上 detail without-paging」，不符合實際原因。I01 的訊息應該在區塊含 RouterOS 錯誤訊息時另外說明。**已處理**：整段只有 RouterOS 錯誤訊息時，I01 的訊息改為「指令執行錯誤：<第一行>」，並提醒確認 RouterOS 版本與已安裝的套件是否支援這個指令（`src/check/checks.js`）。
