# ADR-018：畫面只透過 Q 與 S.query.* 讀資料，並以守門測試強制

- **狀態**：已接受
- **日期**：2026-10-24
- **決策者**：使用者（同意主對話的建議）

## 背景

- 畫面原本有約 60 處直接讀 Snapshot 的欄位（`snap.findings`、`meta`、`coverage`、`blocks`、`model.devices`），以及核心內部的 `S.check.CATALOG`、`DATA_LABEL`、`fmtVlans` 與 `S.adapters[id].label`。
- M3 會升為 `ssot-snapshot/3`，改變 IP 與路由的鍵（[ADR-015](015-支援VRF並升級ssot-snapshot-3.md)）。畫面直接讀欄位的地方不經過查詢介面 Q，到時候 Q 擋不住，要逐一找出來改。
- 「畫面只讀 Q」原本只寫在文件裡（`CLAUDE.md`、[設計說明 §11](../設計說明.md#11-檢視層架構)），沒有測試強制，所以一直有新的直接讀取。

## 決策

1. `src/view` 只透過 `S.query(snap)`（Q）與 `S.query.*` 的靜態函式讀資料。畫面需要的資料 Q 沒有時，由 data-model 新增查詢函式，畫面不繞過。這次新增的函式（98faca7）：`Q.finding`、`findingIndexByKey`／`findingIndexesByKey`、`findingsByRule`、`blocksOf`、`coverageOf`，`S.query.rule`／`rules`／`dataLabel`／`adapterLabel`／`metaOf`，以及移到 `S.util` 的 `fmtVlans`（[設計說明 §5.2](../設計說明.md#52-實體snapshotmodelschema-ssot-snapshot2)）。
2. **規則目錄是靜態資料**，放在 `S.query.rule`／`rules`，不放在 Q。
3. **選取鍵用 idx**；跨基準時用 findingKey，再以 `Q.findingIndexByKey` 換回 idx。
4. **唯讀政策**：Snapshot 靠約定唯讀；Q 的衍生索引與規則目錄凍結。
5. `S.readers.PASTE`、`S.profile.compile`、`S.inputHashOf` 屬於輸入 API，畫面可以使用。
6. 允許與禁止的清單由 `tests/ui-smoke.js` 的邊界掃描強制（`VIEW_S_ALLOW`、`VIEW_S_ONLY`，清單見[設計說明 §11](../設計說明.md#11-檢視層架構)）；另外以深層凍結的基準跑過畫面的主要操作，確認畫面不改寫基準（[開發指南 §3](../開發指南.md#3-測試)）。

實作：查詢函式在 [src/query/query.js](../../src/query/query.js)（98faca7），畫面改寫與守門測試在 4dabc00。

## 考慮過的選項

| 選項 | 理由 | 結論 |
|---|---|---|
| A. 每次查詢都複製 | 1000 台時，每次重繪都要重建大陣列 | 不採用 |
| B. 在 query 裡深層凍結 Snapshot | 會改到呼叫端的物件、成本是 O(全部)，也和現有測試衝突 | 不採用 |
| C. 約定唯讀，衍生資料凍結，加上守門測試 | 不複製、不改呼叫端的物件；違規由測試擋下，並列出檔案、行號與建議寫法 | **採用** |
| D. 規則目錄放在 Q | 會讓人誤以為是建立基準當時的目錄；`advice(id)` 手上沒有 Q | 不採用 |
| E. 新開 `S.rules`、`S.format` 命名空間 | 要新增核心檔案、改載入順序 | 不採用 |
| F. 選取改用 findingKey | 鍵會碰撞（[ADR-003](003-findingKey的組成.md)） | 不採用 |

另外考慮過引入完整的狀態管理（事件匯流排、store 訂閱）。只有一個使用者、一個畫面，太重，不採用。

## 後果

### 變容易的

- M3 改鍵時，只要改 Q 與它的呼叫端；畫面不會有漏掉的直接讀取。
- 守門測試擋下直接讀欄位的寫法：改寫前掃到約 60 處，改寫後是 0。違規訊息附上建議的查詢函式。

### 變困難的

- 畫面需要新資料時，要先由 data-model 新增 query 函式，不能在畫面直接讀。
- 邊界掃描是簡化的掃描器（去掉註解、字串與 regex 後比對），不是完整的 JavaScript parser；寫法特殊時可能誤判，要調整寫法或掃描器。
- [ADR-006](006-規則目錄與判斷分開.md) 的「畫面直接讀 `S.check.CATALOG`」「advice 從 `S.check.CATALOG` 讀取」改為經 `S.query.rule`，見該 ADR 的「修訂」。

### 之後要回頭看的

- 資料中心會把「這一輪的資料」（基準、輸入、命名規則、處理紀錄等）集中成單一狀態物件（[路線圖「版面重整 1」](../路線圖.md#版面重整-1資料中心工作包)）。**已處理**（8f8523e）：`App.round`，只能經 `A.load`／`A.setRoundInputs`／`A.clearRound` 改變（[設計說明 §11](../設計說明.md#11-檢視層架構)）。
