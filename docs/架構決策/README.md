# 架構決策紀錄（ADR）

這裡記錄影響整個專案的決策：當時的背景、考慮過的選項、取捨與後果。程式的現況以程式與各份文件為準，ADR 只說明「為什麼這樣做」，規格不在這裡重寫一份，而是連結到程式或文件。

格式參考 [Architectural Decision Records](https://adr.github.io/)。

## 狀態

- **提議**：已寫出建議，尚待使用者決定。
- **已接受**：使用者已決定，程式依此實作（或依此規劃）。
- **已否決**：考慮過但不採用；保留檔案，說明為什麼不做。
- **已取代**：被後來的 ADR 取代，狀態寫成「已取代（見 ADR-xxx）」。

## 格式

每份 ADR 依序包含：

1. **標題**：`# ADR-編號：決策的一句話`
2. **狀態**、**日期**、**決策者**
3. **背景**：要解決的問題、當時的限制
4. **決策**：決定了什麼；已接受的決策要對照程式寫出依據的檔案
5. **考慮過的選項**：每個選項的優點、缺點與結論，用取捨表列出
6. **後果**：分成「變容易的」「變困難的」「之後要回頭看的」
7. **待辦**：要由誰（agent）做什麼

## 新增方式

1. 取下一個編號（三位數），檔名用中文：`<編號>-<決策摘要>.md`，例如 `014-某某決策.md`。
2. 依上面的格式撰寫。決策者是使用者。尚未決定時狀態寫「提議」，使用者決定後改為「已接受」或「已否決」，日期改為決定的日期。
3. 寫「已有」「會」之前先對照程式；規格只連結到程式或文件，不複製。
4. 已接受的 ADR 不改寫決策內容。決定改變時新增一份 ADR，把舊的狀態改成「已取代（見 ADR-新編號）」。修正錯字、補連結不在此限。
5. 更新本頁的索引。
6. 執行 `npm run test:docs` 與 `git diff --check`。
